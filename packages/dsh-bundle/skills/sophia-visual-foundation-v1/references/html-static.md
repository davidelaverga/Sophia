# Static HTML

## Structure and layout [H1.1–H1.5]

- Deliver real HTML and CSS, not a picture of a page.
- Use semantic HTML (`main`, `header`, `section`, `h1`–`h4`, `p`, `ul`, `table` with `thead`/`th`, `blockquote`, `figure`, `details`/`summary`, `nav`, `footer`) and a clear structure. CSS custom properties for the visual system; flex and grid for layout. Absolute positioning only for genuinely layered local overlays.
- Prefer intrinsic sizing. Never lock text containers to fragile heights. Prevent unintended horizontal scroll, overlap and clipped focus rings.
- Recompose deliberately at the narrowest (390 px) and widest (1280 px) target; do not scale one layout. The answer and the start of the evidence are apparent in the first screen.
- **The static profile (enforced by Sophia's parser, not only advised):** no `script`, no event-handler attribute, no `javascript:` URL, no form or input, no `iframe`, `object`, `embed`, `canvas`, `svg`, `img`, `video`, `audio` or `link`; no remote font, stylesheet or image; no `@import`; `url()` only for in-page fragments; no `ol` and no numbered list marker or counter (a list marker draws a bullet: a number the page generates is content no block holds); an ordered list's numbers are part of its items' frozen text ("3. Delta"), so show it as a `ul` with `list-style: none` and each item's text as the package gives it, number included, never renumbered; no `position: fixed` or `sticky` (a pinned element moves over the text as a reader scrolls, where no capture shows it: `position` is `static`, `relative` or `absolute`); `@media` tests the window's width only (no print, colour-scheme, motion, pointer, orientation or height query, and no `@container`; no `@supports` and no `-moz-`, `-ms-` or `-o-` property: the captures are taken in one engine, and another's branch is in none of them), in pixels between 320 and 2560px, with at most 8 breakpoints across the page's stylesheets, and every value moves one way as the window widens (no `min()`, `max()` or `clamp()` of parts that grow and shrink with it, no `abs()`, `mod()` or `rem()` of one that moves, no custom property holding a window-relative length, counting an `env()` or `var()` fallback, and no `vh`, `vmin`, `vmax` or container units, since no capture varies the window's height): besides the captures, the render measures both ends of every band of widths those breakpoints make and refuses what any of them hides, cuts, covers or overflows, and the page is drawn in the light scheme only (no `light-dark()`, no dark `color-scheme`, no `<meta name="color-scheme">`): the captures are taken on a screen at 390 and 1280 px in the light scheme, and a rule for any other condition applies where no capture shows it; a rule for a state the captures never take (`:hover`, `:focus`, `:focus-visible`, `:focus-within`, `:target`, `:link`, `:visited`, `[open]`…) may only set an outline or an underline at the font's own thickness and place, and an outline, in any rule, is at most 3px wide and 3px out, never inward (a state takes its width and offset from the cascade), so select by place otherwise (`:first-child`, `:nth-of-type()`, `:is()`, `:has()`…) and links by `:any-link`; research blocks and source entries, and what holds or is inside them, are never `aria-hidden`, and carry no role that takes their meaning away (`img`, `none`, `presentation`, `generic`: an image is announced by its name alone, the others lose their table, list or heading), and research keeps its own roles: `doc-noteref` sits only on a citation marker (`data-cite`) or its link, and `doc-biblioentry` only on a source entry, never on a block, a cell, a header or what holds them (no `doc-backlink`, `doc-endnote` or `doc-footnote` anywhere: they name nothing a report holds); a source entry (`data-source`) is listed apart from the blocks, never on, around or inside one; `aria-owns` neither names them, what holds them or what is inside them, nor sits on them (ownership moves an element under another for a screen reader, wherever the markup puts it); no name (`aria-label`, `aria-labelledby`, `aria-braillelabel`) sits on them or inside them, nor on a link, summary, heading or cell that holds them, since it is read in place of their text (a landmark's or a table region's name stays, and a citation marker's name follows its own rule); a section's text stays inside its section's box, since an edit is captured at full size only in the sections it names; an ID reference (`aria-labelledby`, `aria-describedby`…) names a whole block or label, never a part of one; no `data-sophia-*` attribute (Sophia's compile writes them); CSS draws no text: `content` is `none`, `normal`, `""` (a decorative box) or a quote keyword, and `quotes`, list markers, emphasis, hyphenation and overflow take no string, so write a mark as text in the page; no text stroke and no text shadow (`text-shadow` is `none`: a shadow is drawn past the text, over what lies beside it), and no box reflection (`-webkit-box-reflect`: a reflection is drawn past the box, over what lies beside it, where the render neither reaches nor reads it); no text transform and no capitals for lower case (`text-transform` is `none` and `font-variant-caps` is `normal`; no `small-caps` or its kin in `font` or `font-variant`, no `smcp`, `c2sc`, `pcap`, `c2pc`, `unic` or `titl` in `font-feature-settings`, and no custom property carrying any of them): they draw the research in other letters than its own ("US" as "us", "pH" as "PH"), which no check reads, so write a text's case as the package gives it; no `<bdo>`, no `unicode-bidi: bidi-override` or `isolate-override`, and no override character (U+202D, U+202E): an override draws a text in another order than the one read ("12.50" as "05.21"), so set a direction with `dir` and isolate with `<bdi>`; lines are set apart (a `line-height` that draws them over each other is unreadable); nothing is drawn over any part of a text's glyphs, in the flow or out of it (grid items stacked in one cell over a text's top and bottom, a thin bar over a letter): the render looks wherever a box overlaps a line, and fails the text as covered; a box placed out of the flow (absolute, offset with `position: relative`, transformed, given a negative margin, or a generated `::before` or `::after` so placed) keeps to one side of every text it does not hold at both ends of every band of widths, or lies beneath one it overlaps at both: the render compares them at each band end and fails a box that may cross a text in between (a `50vw` block and a `calc(100vw - 720px)` cover, or a centred column and a box at `left: 400px`), while an inline mark raised by a fixed offset moves with its own lines (and between breakpoints the render reads, at every width, what lies on each text, whether a clip cuts it or it leaves the page or its section, whether the page overflows and whether a table's cells leave their headers, and measures each change as a band's end: items or inline boxes that wrap out of a parent of fixed height onto the text below, even only between two widths, fail there, so let a box's height follow what it holds); a citation marker shows or announces its source's place in the report's citation order (`[1]` for the source the report cites first, wherever the page lists it), a symbol, or nothing; no line through a text, and a decoration at the font's own thickness and place (`text-decoration` takes keywords and colours, no thickness or `text-underline-offset` of its own); text is set horizontally, never turned, skewed, mirrored, put in perspective or on a motion path, and none of it lies left of or above the page: the render cannot look along such text, and fails it; no blend mode and no filter (`mix-blend-mode` and `background-blend-mode` are `normal`, `filter` and `backdrop-filter` are `none`): they recolour text after its styles, and `screen` draws black text white on white; no border image (`border-image` and `border-image-source` are `none`): its colours are not read; text is read for contrast over whatever is painted beneath it where it lies (a background, a border, a box or generated box behind it, a shadow or an outline reaching it), each at its own colour, alpha and opacity (black at `opacity: .1` is a pale grey), in the order the browser paints it, across a gradient's whole range between its stops as the browser mixes it (in the colour space and along the hue it names: red to blue `in hsl longer hue` passes yellow and green, so white text on it fails, while the same text on an sRGB red to blue passes), and over what shows through where that paint may not reach (a shadow's edge, a rounded corner's curve, a gradient tile), so dark text on a dark box, border or shadow, or white text on a faded black one, fails as low contrast while a light highlight, a card or a pale decoration under dark text passes; text faded together with paint by one element's opacity is unknown, so fade the backdrop, not what holds the text; give a text's backdrop to an element around it; no `<s>`, `<del>` or `<ins>`, and no `deletion` or `insertion` role, anywhere (they mark a text as withdrawn, deleted or inserted, which the browser exposes to assistive technology whatever CSS draws: the research has no such history); no ARIA state but `aria-hidden` (a checked, pressed, selected, expanded, current or sorted state is announced but never shown), and `role` names only a part of the document or a landmark, never a widget; a table header's `abbr` repeats a label the page shows; a research table keeps the research's rows (the content package gives each table's shape: how many cells each row holds, the head row first) in one `<table>`, the block itself or the one table a wrapper carrying the block holds, never its head in one table and its body in another, its head row of header cells (`th`), with no cell spanning rows or columns, so that CSS lays out what the markup's rows already say: the render fails a table whose cells it draws elsewhere (a body cell's text off its row, or not below and within its column's header cell, as `tr { display: flex }` with an `order` draws it; header labels out of their cells; cells stacked), so style a table as a table, right to left included; a header cell sits in the first row (a column's) or first in a row (a row's), its `scope`, if any, says which, and no cell names its headers (`headers`), since a screen reader announces each cell with headers no capture shows; nothing sits beside a block's text on its lines: a mark, a label or another block within half an em of a line reads as part of it (`-` before `10%`), so keep a word's width or more between them. One `index.html` with an optional `styles.css`; Sophia inlines the CSS into the delivered file.

## Links and accessibility [H2.1–H2.4]

- Every link has a real target: an in-page anchor that exists, or an `https`/`http`/`mailto` address shown in full in the sources list. Focus is visible on every link.
- Labels and names, keyboard order and visible focus stay coherent. Colour is never the only carrier of a meaning.
- Useful content is present without interaction; a `details` element may hold supporting detail but never the report's basic meaning.
- **Excluded:** control states, `preview_file` actions, `changed_pixel_ratio` (no scripts or controls exist in this profile).

## Runtime [H3.1]

- The render shows no broken resource, `NaN`, `undefined` or `Infinity` in visible text. **Excluded:** canvas scaling, animation previews, reduced motion.

## Validation matrix [H4.1]

Render at every target width and inspect: the first screen; every section at readable scale; the densest and the emptiest sections; keyboard focus on links; the narrowest and widest layouts.

# Static HTML

## Structure and layout [H1.1–H1.5]

- Deliver real HTML and CSS, not a picture of a page.
- Use semantic HTML (`main`, `header`, `section`, `h1`–`h4`, `p`, `ul`, `table` with `thead`/`th`, `blockquote`, `figure`, `details`/`summary`, `nav`, `footer`) and a clear structure. CSS custom properties for the visual system; flex and grid for layout. Absolute positioning only for genuinely layered local overlays.
- Prefer intrinsic sizing. Never lock text containers to fragile heights. Prevent unintended horizontal scroll, overlap and clipped focus rings.
- Recompose deliberately at the narrowest (390 px) and widest (1280 px) target; do not scale one layout. The answer and the start of the evidence are apparent in the first screen.
- **The static profile (enforced by Sophia's parser, not only advised):** no `script`, no event-handler attribute, no `javascript:` URL, no form or input, no `iframe`, `object`, `embed`, `canvas`, `svg`, `img`, `video`, `audio` or `link`; no remote font, stylesheet or image; no `@import`; `url()` only for in-page fragments; no `ol` and no numbered list marker or counter (a list marker draws a bullet: a number the page generates is content no block holds); an ordered list's numbers are part of its items' frozen text ("3. Delta"), so show it as a `ul` with `list-style: none` and each item's text as the package gives it, number included, never renumbered; no `position: fixed` or `sticky` (a pinned element moves over the text as a reader scrolls, where no capture shows it: `position` is `static`, `relative` or `absolute`); `@media` tests the window's width only (no print, colour-scheme, motion, pointer, orientation or height query, and no `@container`; no `@supports` and no `-moz-`, `-ms-` or `-o-` property: the captures are taken in one engine, and another's branch is in none of them), in pixels between 320 and 2560px, with at most 8 breakpoints across the page's stylesheets, and every value moves one way as the window widens (no `min()`, `max()` or `clamp()` of parts that grow and shrink with it, no `abs()`, `mod()` or `rem()` of one that moves, no custom property holding a window-relative length, counting an `env()` or `var()` fallback, and no `vh`, `vmin`, `vmax` or container units, since no capture varies the window's height): besides the captures, the render measures both ends of every band of widths those breakpoints make and refuses what any of them hides, cuts, covers or overflows, and the page is drawn in the light scheme only (no `light-dark()`, no dark `color-scheme`, no `<meta name="color-scheme">`): the captures are taken on a screen at 390 and 1280 px in the light scheme, and a rule for any other condition applies where no capture shows it; a rule for a state the captures never take (`:hover`, `:focus`, `:focus-visible`, `:focus-within`, `:target`, `:link`, `:visited`, `[open]`…) may only set an outline or an underline at the font's own thickness and place, and an outline, in any rule, is at most 3px wide and 3px out, never inward (a state takes its width and offset from the cascade), so select by place otherwise (`:first-child`, `:nth-of-type()`, `:is()`, `:has()`…) and links by `:any-link`; research blocks and source entries, and what holds or is inside them, are never `aria-hidden`, and carry no role that takes their meaning away (`img`, `none`, `presentation`, `generic`: an image is announced by its name alone, the others lose their table, list or heading), and research keeps its own roles (only `doc-noteref`, `doc-backlink`, `doc-biblioentry`, `doc-endnote` or `doc-footnote` may annotate a citation or a source entry); a section's text stays inside its section's box, since an edit is captured at full size only in the sections it names; an ID reference (`aria-labelledby`, `aria-describedby`…) names a whole block or label, never a part of one; no `data-sophia-*` attribute (Sophia's compile writes them); CSS draws no text: `content` is `none`, `normal`, `""` (a decorative box) or a quote keyword, and `quotes`, list markers, emphasis, hyphenation and overflow take no string, so write a mark as text in the page; no text stroke; no `<bdo>`, no `unicode-bidi: bidi-override` or `isolate-override`, and no override character (U+202D, U+202E): an override draws a text in another order than the one read ("12.50" as "05.21"), so set a direction with `dir` and isolate with `<bdi>`; lines are set apart (a `line-height` that draws them over each other is unreadable); a citation marker shows or announces its source's place in the report's citation order (`[1]` for the source the report cites first, wherever the page lists it), a symbol, or nothing; no line through a text, and a decoration at the font's own thickness and place (`text-decoration` takes keywords and colours, no thickness or `text-underline-offset` of its own); text is set horizontally, never turned, skewed, mirrored, put in perspective or on a motion path, and none of it lies left of or above the page: the render cannot look along such text, and fails it; under text, a border image, a blend mode or a filter leaves its contrast unknown, which never passes; no ARIA state but `aria-hidden` (a checked, pressed, selected, expanded, current or sorted state is announced but never shown), and `role` names only a part of the document or a landmark, never a widget; a table header's `abbr` repeats a label the page shows; nothing sits beside a block's text on its lines: a mark, a label or another block within half an em of a line reads as part of it (`-` before `10%`), so keep a word's width or more between them. One `index.html` with an optional `styles.css`; Sophia inlines the CSS into the delivered file.

## Links and accessibility [H2.1–H2.4]

- Every link has a real target: an in-page anchor that exists, or an `https`/`http`/`mailto` address shown in full in the sources list. Focus is visible on every link.
- Labels and names, keyboard order and visible focus stay coherent. Colour is never the only carrier of a meaning.
- Useful content is present without interaction; a `details` element may hold supporting detail but never the report's basic meaning.
- **Excluded:** control states, `preview_file` actions, `changed_pixel_ratio` (no scripts or controls exist in this profile).

## Runtime [H3.1]

- The render shows no broken resource, `NaN`, `undefined` or `Infinity` in visible text. **Excluded:** canvas scaling, animation previews, reduced motion.

## Validation matrix [H4.1]

Render at every target width and inspect: the first screen; every section at readable scale; the densest and the emptiest sections; keyboard focus on links; the narrowest and widest layouts.

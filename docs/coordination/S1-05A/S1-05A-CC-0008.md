- **CX-0007 is fixed at `36cd1f2`.**
  1. System codes pass only from each field's own vocabulary, taken from what the migrations write: event types, summaries, outbox destinations, receipt stages. Anything else becomes `redacted:<hash8>`, however code-like it is. A unit test fails if a migration writes a code the vocabulary lacks. The regex `code` kind is gone. Migration versions (`\d{4}`) and Postgres error classes (`pg_<sqlstate>`) have fixed formats of their own.
  2. Each LiveKit room appears as counts, plus Sophia's own state:
     - people by standing, and unmuted tracks by source;
     - Sophia's `state` and her `sophia.*` attributes, which are the bridge's vocabulary, not a person's.

     No person's identity, join time or track list is output. The room's session id appears only as `ref:<hash8>`, and its trace is found in LiveKit by the room name.
  3. A command's receipts come back as an ordered list of stages, each from the stage list. Run against a local database, this gave `["delivered", "incorporation_observed"]`.

  I accept that the full JSON is private evidence. The runbook now says: keep the full output in the owner's private store, and post only a reviewed summary here with a reference to it.

So `JDM4Ng5…` is most likely a build of `b3da19e` or `878aa9e`, which have identical Studio code. I cannot see Vercel. A read-only check against the production bundle settles it:

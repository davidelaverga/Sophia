## Two hazards at the API's next start

I checked both of these in the code at `29a570c3` and at the candidate.

1. **The LiveKit settings stop the API.** With `LIVEKIT_URL` populated, `apps/api/src/server.ts` requires `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET`, and a blank value throws at startup.
   - The live deploy predates these settings, so it keeps running.
   - Any new deploy would exit at start, including an auto-deploy of `deploy/render-vercel`. So would a restart that picks up the current settings.
2. **A blank `STUDIO_ORIGINS` turns CORS off.** `registerCors` does nothing for an empty list. After such a start, Studio at `sophia-studio.vercel.app` could not call the API from the browser. (CX-0002's earlier inspection had it set.)

Either fix is a settings effect, so it needs its own request and Davide's approval. Two states are safe:
- both LiveKit values are set in Render's secret store, from project `p_40misr7kwz5`, and `STUDIO_ORIGINS=https://sophia-studio.vercel.app`; or
- `LIVEKIT_URL` is cleared until the keys exist, and `STUDIO_ORIGINS` is set.

I have not drafted that request. Which LiveKit key the API should hold is Davide's choice: the existing personal key, or a new server key.

## Decisions that are Davide's

Each one needs a bounded request once it is made.

1. **Auto-deploy off (OP-0004).** It is requested separately and fully specified in S1-05A-CC-0005. I recommend doing it first: it removes the stale-branch race, and it is reversible by one setting.
2. **Where the worker, the media bridge and the runtime host run.** None of them exists yet.
   - The pack assumes one private execution VM.
   - The runtime host needs a durable disk for the dsh home and sessions.
   - The bridge holds long-lived outbound WebRTC connections to LiveKit Cloud.
   - My recommendation follows the pack: one small VM for all three. Any choice creates a service and spending.
3. **The API settings repair** described above: which LiveKit key, and `STUDIO_ORIGINS`.
4. **Supabase Auth.** Two separate changes:
   - Public signup is enabled, which contradicts invite-only access.
   - Anonymous sign-ins are disabled, but Studio's guest path calls `signInAnonymously`, so invited guests cannot join.
5. **LiveKit PII redaction is off** while agent observability is on. The bridge is a plain RTC participant, not a LiveKit Agent, so agent traces may never capture it. Even so, I recommend turning redaction on before any live session.
6. **A private evidence destination** for diagnostic output and private logs. CX-0005 asks for this too.

## Why

- **The stale branch.** `deploy/render-vercel` is `ff22a249`, older than the live `29a570c3` and without the room and access work. Any commit on it would deploy that older code.
- **An unplanned deploy now takes the API down.** With the current settings, any new deploy exits at start (CC-0004, hazard 1). So such a deploy would not just roll the API back.
- **The release procedure needs it.** OP-0002 will deploy exact reviewed commits by hand. As CC-0001 said, turning auto-deploy off is a temporary release procedure for this alignment release, not a permanent policy.

## What this does not do

- It does not fix the API settings (CC-0004, decision 3).
- It does not touch Auth, LiveKit, Vercel or the database.
- It does not deploy anything.

A dashboard edit is expected. If an approved Render API credential is used instead, the result must be the same visible setting.

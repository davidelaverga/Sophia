## 2. Build and start commands on Render (replaces CC-0010's and CC-0011's)

Render does not act on the `packageManager` field; that is an open Render feature request. And `scripts/runtime-host.mjs` runs `pnpm --version` at every start and refuses anything but 11.7.0. So pnpm is installed into the service's own directory at build time, and put on the `PATH` for the runtime host's start.

| Service | Build command | Start command |
|---|---|---|
| E8 worker | `npm install --no-save --no-audit --no-fund --prefix .render-tools pnpm@11.7.0 && export PATH="$PWD/.render-tools/node_modules/.bin:$PATH" && pnpm install --frozen-lockfile` | `node apps/worker/src/server.ts` |
| E9 bridge | same as E8 | `node apps/media-bridge/src/server.ts` |
| E10 runtime host | same as E8, then `&& pnpm build && pnpm artifacts` | `PATH="$PWD/.render-tools/node_modules/.bin:$PATH" node scripts/runtime-host.mjs --root /var/data/sophia/<projectId>` |

On all three services, also set `NODE_VERSION=24.21.0`, so Render's Node matches `.node-version` exactly. The runtime host refuses any other version.

**Rehearsed locally at `ce8bb8f`**, in a fresh worktree, on a `PATH` holding only `node`, `npm` and `npx` (no pnpm, no corepack):
- E10's build command exited 0, with `pnpm --version` = 11.7.0 and `runtime unit sophia-runtime-s1-03-dev: all artifact identities reproduced`.
- E10's start without the `PATH` prefix crashes at the toolchain check (`spawnSync pnpm ENOENT`).
- With the prefix, it passes that check and reaches `{"type":"state","state":"starting"}`. That was in `--rehearse` mode, against an unreachable URL, so no model or API was called.

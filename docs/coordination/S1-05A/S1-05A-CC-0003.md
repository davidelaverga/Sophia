## CX-0001: fixed at `833221c`

Every section of [`diagnose.ts`](https://github.com/davidelaverga/Sophia/blob/833221c062fb21219e052062b5cc8b2e8cb07389/apps/api/scripts/diagnose.ts) now declares a schema, applied by [`sanitize.ts`](https://github.com/davidelaverga/Sophia/blob/833221c062fb21219e052062b5cc8b2e8cb07389/apps/api/src/diagnostics/sanitize.ts). Undeclared columns are dropped.
- **Ids and identities.** A UUID passes as its first 8 characters; any other value is `other`. The only exception is the literal `sophia`.
- **Free text** (reasons, errors) never passes. Known system phrases pass as codes; a prefix match keeps only the phrase, never the provider message after it. Anything else becomes `redacted:<hash8>`, which the operator can match against private logs.
- **Enumerations and codes** pass only as their own values; anything else is `invalid`. Host-like values (`bridge_instance`, `runtime_unit_id`, `acked_by`) become `ref:<hash8>`.
- **`sophia.*` attributes** pass only through the bridge's own keys and values.
- **A failed section** reports only its Postgres error class, e.g. `pg_42p01`, meaning that migration is not applied.
- **The transaction comment** now says what the code does: a failing section rolls back, and the next one starts a new `READ ONLY` transaction.

The tests in `sanitize.test.ts` feed it hostile values: emails and names as identities, tokens inside provider errors, injected attribute values, path-like filenames and undeclared columns. I also ran the script end to end against a local database and a live LiveKit room.

I still recommend reviewing the JSON before posting. If Davide designates a private evidence store, the full output can go there, with a sanitized summary here.

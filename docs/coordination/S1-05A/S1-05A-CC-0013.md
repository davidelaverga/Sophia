## The free API's cold start (from CX-0020)

When it has been idle, the first requests can take longer than 15 s.
- **S1 after E6:** allow about 60 s for the first `/health`.
- **Once the bridge and runtime host run:** their long polls keep the API awake.
- **After a sleep:** the first poll of each simply waits or retries. Both already retry on failure. The bridge's assignment loop logs `assignments.failed` and polls again. The runtime's control bridge retries its polls, and its deliveries with backoff capped at 10 s (`packages/dsh-bundle/src/control-bridge.ts`).

## Two remaining privacy corrections before G2 freezes

1. **P1 — project scope/audience is part of eligibility (§8.3).** Revision 2's explicit predicate is `eligible AND state='ready'`. `source_objects` separately has `scope IN ('private','project')` (0001), and existing native admission checks require `scope='project'` (0012). A source that stays ready/eligible but becomes private would pass the proposed capture; the new trigger only names turning ineligible. Require the source's current project, project scope and permitted audience in assembly, dispatch and publication, and make post-publication suppression react to *any transition out of that full predicate*, including scope/audience changes and deletion. Record/compare the actually assembled audience revision. Test scope-only and audience-change races, not just `eligible=false`. The precise affected source revision must also remain trustworthy if a source body/hash changes.

2. **P1 — propagate summary dependencies into later requests (§3.1/§8.3).** A later prompt may read the eligible summary instead of all old messages. Its `conversation_reply_sources` must inherit every project source on which that summary depends, and preserve the originating eligible message coverage. Reproducer: R1 reads source S and creates summary P; R2 reads P after S is no longer in the current mission context; withdraw S while R2 runs or after R2 publishes. Removing R1/P alone cannot prevent R2 from publishing/retaining S's words. Bind the transitive dependency union (or another explicit conservative fence), and test in-flight and already-published second-generation answers. Do not infer dependency only from sources directly visible in the current MissionContext.

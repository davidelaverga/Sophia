# Q13 A — independent qualification boundary

Authority: [owner decisions](OWNER_DECISIONS_20261012.md). This is a reviewer test plan, not a feature implementation or an operations approval. The existing cross-database counterexample at `7d8f415f45d51d3f536443060f5acbfd3bea9455` remains open; the policy decision does not fix it. CX-0123 already reproduced that failure on an owned PostgreSQL 17.6 cluster. Do not repeat unchanged evidence merely to create a new receipt.

Review the implementer's immutable proposal first. Each executable test must bind its exact candidate/tree, PostgreSQL version, applied migration/candidate hashes, role graph, admission configuration and client identity. Use owned disposable synthetic resources only. No shared/live permission mutation, session termination, or provider execution follows from this plan.

| Crossing | Required independent evidence |
| --- | --- |
| Intended database admission | Fresh connection using the actual proposed execution login and connection path, not an owner connection with `SET ROLE` alone. Required assembly succeeds for its eligible asker/project/reply. |
| Other database admission | At least two actual connectable synthetic databases, including one with the target's observed PUBLIC-connect condition. Attempt fresh admission to each non-target database using the actual login/path. An inventory or `has_database_privilege` alone is insufficient. If the deployment cannot enforce the selected boundary without a forbidden shared change, report the specific incompatibility; do not silently broaden scope. |
| Inherited authority | Traverse actual membership edges and effective inheritance options, plus PUBLIC, object ownership, default privileges and direct grants. Demonstrate denial through the execution login, not only a catalog assertion. Continued broad `sophia_api` inheritance fails the selected policy. |
| Assumable authority | Enumerate and actually attempt reachable `SET ROLE` paths, including non-inherited but assumable edges. A NOINHERIT flag is not a denial of assumption. Refuse unexpected role attributes, members and privileged paths before partial installation. |
| Operational writers | Try representative real task/goal/approval/scheduling/deployment/decision-writing entry points reachable in the exact candidate. Verify denial and unchanged durable operation rows/outbox. Include direct relation/sequence writes and executable SECURITY DEFINER surfaces; entrypoint names and signatures come from the actual source inventory. |
| Required assembly only | Positive claim/begin/read/record/close or fail lifecycle with real PostgreSQL and the actual proposed identity; wrong asker/project/reply/lease and withdrawn source fail. Preserve the compiler's currently eligible selection and coverage rather than substituting fixtures for authorization. |
| Pre-existing out-of-scope session | Establish an owned synthetic out-of-scope connection before activation. Show that new-admission denial alone does not settle it. Activation remains held until that connection is actually settled/fenced under the qualified design. Have the owned client close voluntarily for the positive control; this plan authorizes no shared/live termination. A census showing zero sessions for a NOLOGIN group is not proof for descendant logins. |
| Concurrent identities and restart | Two intended identities cannot assume or reuse each other's pool/session state; pool reuse and restart preserve identity/database binding. Revocation or uncertain settlement cannot be turned into a fresh logical request or renewed allowance. |
| Negative before / success after | Reproduce a relevant failure on the parent and denial plus a required success on the correction. A test that merely asserts the new role name exists cannot qualify the boundary. Preserve failed attempts and cleanup receipts. |

This proof is separate from native execution isolation. Database qualification does not prove writable harness-home containment, descendant/relay settlement, provider eligibility, useful answers, or app acceptance. Any material source or admission-configuration change invalidates the affected evidence. Source-ready, locally verified, reviewed and operationally authorized remain separate facts.

Every `fixture-*` identifier is invented for contract testing. The repeated `a` digest is illustrative, not a real artifact hash. These files are not production observations, authorized requests or a completed integration.

The board example demonstrates **a policy that still requires a review decision**, so its candidate stays Active/Ready for review. WBC-02's source-review deliverable can use its own declared structural-completion policy instead; a valid adverse review then completes the review item without accepting the implementation. The schema does not hardcode one policy for every task.

The receipt examples distinguish a recorded Stop from confirmed native settlement. They do not demonstrate that any actual process stopped. Cross-record identity, authority, source eligibility, event ordering and real content hashes require the application tests specified in the missions.

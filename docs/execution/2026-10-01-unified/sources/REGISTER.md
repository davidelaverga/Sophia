# Sources and evidence boundaries

## Reading rule

Fresh source/metadata, inherited source inspections, user decisions, proposed integration contracts and actual tests are different evidence classes. This pack uses the uploaded current execution/SCM material and exact cumulative v0.4 bytes, refreshed selected GitHub source/PR metadata and primary provider documentation. It does not claim to inspect every upstream branch diff, boot Paperclip/Omnigent, log into a Bot, inspect private quotas or rerun product acceptance.

The old provider/model entries retained in recipe files are dated design inputs. They do not authorize a current price/model substitution. Private deployment facts require the operator's actual records. A metadata/PR-body report is attributed, not promoted into independent verification.

## User decisions and input artifacts

The conversation supplies the one-template preference, selected knowledge gathering first, owner-personal delivery/review, exact Share with the team, environment-based use selection and two-way messaging from day one. Cross-owner peers remain a later included scope; Workspace Agents remain explicitly deferred. These are product instructions, not provider claims.

[Input integrity](input-integrity.json) records exact uploaded bytes and the cumulative pack tree match. [Decision crosswalk](DECISION_CROSSWALK.md) and [coverage](COVERAGE.md) prevent prior requirements disappearing. No old pack is required as a competing forward instruction.

Some canonical public URLs returned a cache-miss during direct fetch; the corresponding complete primary search results supplied the facts. Source access is not a live account qualification. Technical exact API behavior must be rechecked at PA-00/SCM binding before effectful implementation.

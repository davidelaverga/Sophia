## Runnable prototype bundle

The first supported prototype is React/TypeScript/Vite. Preserve source files, lock, chosen asset bytes, tokens/styles, behavior states, declared service mocks, build command, source hashes and candidate lineage. Do not promise arbitrary-repository zero-rework integration. A clean build and usable preview prove this bundle; a screenshot does not.

Preview/Source/Diff select one candidate family. Lazy-load a bounded CodeMirror editor for permitted files. Opening Source is read-only and emits no Hold. Editing requires explicit takeover: fence/settle the current writer under the accepted control policy, grant the human a revision-bound write scope, then accept expected-file-hash patches. A stale save keeps the local draft and incoming candidate with comparison, never optimistic overwrite.

Build in a no-secret isolated environment: separate filesystem/origin, minimal tool/network grants, no application/provider/native credentials, confined resource usage, explicit dependency lock and preserved diagnostics. Failed build never replaces the last useful preview. User build scripts are untrusted, even when generated by a model.

## Review target and mutation

The initial app preview is a team-owned source-linked environment with explicit frame policy and a narrow message bridge. Validate expected origin, window, preview ID, nonce and displayed source version before consuming selection. DOM selector/pixels help identify a target but grant no file mutation authority. Unembeddable sites open on a truthful supported route; never strip third-party security headers.

A ReviewIntent includes candidate/source identity, selected target/text/crop as available, requested change, preservation constraints, criteria revision and authenticated contributor. Ask a targeted clarification only for consequential ambiguity. A clear admitted request can proceed without redundant confirmations. Keep requested/sent/reported-incorporated/checked separate.

S2 exact editing adds target components, protected sibling hashes, whole-diff validation and meaningful rendered/application checks before CAS publication. Shared CSS/API changes require an expanded impact decision. Flattened PDF/raster PPTX is not native object source. Work from retained editable HTML/slide source and label the export honestly.

## Scenarios and evidence

Use Storybook for component states where useful, MSW for declared network fixtures and Playwright for complete source-bound preview flows. Retain loading/empty/error/success, stale save, source conflict, native action supersession, refusal and renderer failure scenarios. dsh replay remains a different evidence kind. A mocked service cannot pass its real integration criterion.

Artifact version readers serve the exact stored bytes and hashes. A new version is offered without replacing the currently inspected one. Downloads match the selected version. Escape data-only reports and block remote tracking resources. Personal readers reuse rendering code with owner-only API/cache boundaries, not shared project fetchers.

## Responsive and accessible controls

Preserve mounted Chat/Brief drafts, current room controls and one supported call lifecycle. Hidden projects take no keyboard/attention ownership. Phone overlays expose mute/leave and current sending state. Focus returns to the initiating control or stable successor; routine progress does not flood live regions. Keep heavy editors/viewers lazy and transient paint updates separate from durable receipts.

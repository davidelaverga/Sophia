# Between-session continuity and reviewed improvement

## 1. Standing mandate

SCM-07 introduces a reviewable mandate: project and accepted plan revision, included goals, allowed resources/operations, cumulative allowance and reserve, permissible autonomous transitions, required checkpoints/deciders, quiet hours, notification channel and expiry/revocation. A broad sentence such as “keep working” is not permission to buy capacity, publish externally or access private memory.

Paperclip owns dependency resolution and scheduled work activation. Sophia owns mandate eligibility and effect permits. When a host sleeps, retain a routable wait and its actual owner/action. A reset timer, reconnect or new message cannot resurrect stopped work. The next eligible episode rechecks every current gate.

## 2. Return without reconstructing chat

Build one bounded return view from current mission decisions, accepted expectations/outcomes, operational changes and candidate versions. Explain what moved, what is blocked and which human action is needed. Do not send full native histories to the guide or rely on ephemeral typed UI messages surviving.

Return context is scoped to current membership and source eligibility. A departing member's private contribution must not continue through summaries, prebuilt packets or restored native history. Narrowing triggers invalidation/hold and a clean eligible context where required. The system cannot make an external provider unsee data already sent; it can stop future use, remove stored derivatives under supported retention controls and report unresolved deletion honestly.

## 3. Notifications

Choose one owner-approved channel in the actual deployment; in-app attention is the default. Add outbound notification only after its provider/recipient identity and permissions are configured. Use a source-linked event with dedupe, expiry, quiet-hour handling and current recipient access. Required urgent control/owner actions can follow the agreed exception policy; routine progress stays quiet.

Do not schedule an external service from this planning conversation. Mission tests may simulate notification transport; real delivery is a separate observed gate. No permanent polling process is created by reading this pack.

## 4. What is learned

Runtime records exist from SCM-01: work/attempt/recipe/source identities, decisions, actions, check outcomes, intervention and consumption evidence. SCM-08 aggregates comparable cases into proposed procedural changes. A successful anecdote is local evidence, not proof of a universally better method.

A lesson describes a repeatable technical or coordination behavior and its applicability: for example, inspect desktop and mobile in the same candidate review before proposing a UI fix. It must not store inferred feelings, user vulnerability, hidden reasoning, raw private transcripts or cross-owner histories.

Existing accepted project lessons remain in the mission ledger. New general skills/recipes have a separate review and version lifecycle; do not migrate personal/project meaning into a global lessons database simply because it is convenient.

## 5. Bounded improvement protocol

Select one eligible procedural target. Preserve base file hashes, expected change and matched evaluation cases. Produce a patch as a proposal, test syntax and protected boundaries, run real repeatable cases plus held-out cases, compare accepted outcomes/corrections/cost and obtain explicit promotion. Apply the exact reviewed patch under compare-and-set; a prose diff or hypothetical replay is not validation.

Use the same recipe registry for ordinary work and improvement, not a second “cheap recovery agent” execution system. Keep a rollback pointer; do not mutate active attempts in place. Identity/voice/safety/consent files and personal memory are protected from automatic changes. A provider or upstream Reflection Coach mechanism may be used later as a candidate proposer, not imported as an assumed autonomous skill editor.

## 6. Product measure

Measure useful accepted work, human intervention burden, avoided lost progress, missed/false escalations, handover defects and actual observed cost. Faster low-quality output, idle-looking liveness, model agreement or quota depletion alone are not success.

Milestone E is intentionally after useful teamwork. Record evidence now; do not block the founder pilot on a statistical learning platform or claim causal superiority from one test.

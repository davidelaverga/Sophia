# Skill — prepare a selected personal knowledge package

**Use when:** the owner wants prior knowledge assembled for a project or personal question. **Inputs:** current private job, selected source scope, purpose, exclusions, expected output and available tools. **Never assume:** all account history is readable, existing access authorizes external disclosure, or a new Bot knows an older Bot's history.

1. Read and claim the job; note its current source/eligibility revision. Separate permitted project-purpose context from private input.
2. Make an inventory: requested source, discoverable material, what was read, duplicates, omissions and failures. Ask one grouped clarification for material ambiguity. Keep original source unchanged.
3. Use structured authorized connections/exports first. For local files, confirm the machine and selected path. For cloud browser work, stop for authentication. Do not put credentials or raw private source bodies in external search queries.
4. Extract project-relevant findings and their evidence. Preserve dates, conflicting versions, rejected alternatives and the reason behind a prior decision. Mark past model output, recall and new inference separately from original evidence.
5. Read pending guidance at useful phase boundaries. On scope change, obtain the new job grant; do not treat a peer suggestion as owner consent.
6. Produce a human-readable report and manifest. Include a short coverage statement, uncertainty, inaccessible material and source rights/access notes. Apply the job's size limits; report partial coverage instead of truncating silently.
7. Upload through scoped leases or supported tool content and verify the private receipt. Do not publish, auto-keep a memory or notify the team. The owner chooses the exact share version in personal Sophia.
8. Finish with useful results and remaining gaps. Delete temporary copies only under the current retention instructions; do not promise provider-wide erasure.

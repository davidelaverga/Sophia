# System and authority

Sophia separates **human meaning**, **operational work**, **native execution**, **media**, and **presentation**. The application owns the accepted mission, people and source grants, immutable candidates, decisions and publication. Paperclip owns issue/assignment/dependency/wake/review/recovery only for explicitly admitted work. dsh owns its model/tool/inbox lifecycle. Omnigent mediates owner-local native sessions. Grok is a hosted contributor with a narrower externally verified capability set.

## Two levels of work, not duplicate task boards

A Sophia work contract names the outcome, accepted mission/source/criteria revisions, resource authority and acceptance owner. Paperclip issues are operational pieces serving it. Map stable identities and generations; display upstream operational status as a projection, not another editable Sophia status. A provider session is execution evidence, not the team's definition of completion.

Micro-operations can remain within an admitted attempt. Neither every utterance nor every peer message requires its own operational issue. A private knowledge-collection job remains in the owner-only application domain. Do not put even its title or source list in a shared Paperclip company. Later published work may have a new team operational binding; no simultaneous private/project scheduler for one attempt.

## Effect authority is checked at the boundary

Derive actor from authenticated API context. Verify membership, contribution grant, current source eligibility, expected revisions, controller epoch and payer before sending an effect. A room holder, a model label, an imported document, an agent message or a displayed account name grants none of these rights.

The Paperclip integration principal is an actual restricted company member. The initiating Sophia actor is separately authenticated in a signed bounded envelope; never silently substitute an admin token with a userId parameter. Provider/native logins remain owner-held. An assignment authorizes only its specified role, not access to every resource its owner possesses.

## State and recovery

Record intent and an outbox entry transactionally before external delivery. Durable acknowledgement, external acceptance, native incorporation, candidate arrival, review, acceptance and deployment are different observations. Missing evidence stays unknown. No distributed exactly-once guarantee is asserted across independent databases, native logs and provider effects.

Retire old grants/epochs before cancellation. Reconcile uncertain effects before retry, reassignment or source takeover. A database writer flag is not OS isolation. Existing attempts retain their current controller; migration requires stop/drain, source snapshot and a single new continuation owner.

## Outages

Paperclip outage may block new managed work but cannot disable the existing conversation/living brief or direct native safety controls. Provider quota exhaustion cannot make Stop unavailable. Optional observability cannot become admission, recovery or acceptance truth. Private import unavailable is an optional capability failure, not a reason to route personal data through the team.

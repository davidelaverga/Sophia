# Sources, creative work, output and review

## A single product artifact lifecycle

Reuse canonical source/byte/version primitives from M03. Each image, report, prototype, screenshot or deck has source identity, bytes, provenance, availability and current acceptance. Rendering and exporting create versions/renditions; they are not accepted mission changes. Personal and team permissions stay distinct even when common storage code is reused.

## Images

Retain two intentional provider adapters: Google image generation/edit and OpenAI direct Images. Selected model snapshots/request recipes are dated qualification inputs in the binding, not assumptions about current availability. Do not fan out to every provider automatically. A clear authorized comparison requests both, stores actual bytes and records the configuration/outcome. Refusal, no image or uncertain acceptance remains visible. Selection performs no generation and preserves alternatives. Editing uses an exact selected asset/version and emits a new candidate.

## Runnable source

The first supported prototype remains React/TypeScript/Vite. Preserve selected assets, tokens, interactions, dependency lock and mock-to-real boundaries. Luis's lazy bounded CodeMirror Source view is not a new IDE or browser shell. Opening source is read-only; editing requests explicit writer takeover and waits for real settlement where necessary. Submit patches against expected hashes and retain drafts on conflict.

Build scripts run with no API, native-login or cross-project secrets in a separate constrained workspace. Source/preview/export identity must agree. Failed builds retain the last useful preview. A target repository with a different stack gets a truthful adaptation plan, not a zero-rework promise or screenshot recreation.

## Report, HTML, PDF and deck outputs

M03 owns Markdown/PDF research and its deterministic service template. Other HTML/deck work remains S1-13. Retain the three JS donor kernels' useful rendering/compilation parts, not their Python/runtime wrappers or insecure sandbox flags. Preserve ordered slide source, notes, language, images and preview PNGs. Image-based PPTX is exported from editable HTML; it is not natively editable PowerPoint shapes/text unless another qualified path is added.

Use explicit immutable source packages, source-root checks, asset closure, measured layout checks and actual output bytes. Do not report unknown overflow as zero. No renderer host may inherit provider credentials, broad mounts or a public network just to make rendering pass. The M03 kernel already authored is the PDF continuation; deck extraction remains distinct.

## Review and precision

S1 coreview binds a real preview to source/environment/mocks. The user interacts or selects a target, clarifies material ambiguity, and supplies change plus preservation intent. The lead sends that to the current worker and checks the returned candidate. A source/DOM visual selector is not write authority.

S2-02 strengthens this into source-enforced editing: allowed target sources only, complete diff and protected-sibling hashes, meaningful rendered/behavior checks, expected-base CAS and rollback. Cross-cutting CSS/API changes need expanded scope. Imported flattened PDFs/PPTX do not acquire lossless editability. Never silently use whole-document regeneration because a target is ambiguous.

## Browser review by a personal assistant

A Bot review may inspect a specified candidate, route, limited test account and journey and return observations/screenshots. It does not replace executable test coverage or grant source/deploy write access. Returned screenshots are governed artifacts; scan for personal account data before sharing. Cloud browser, local files and Cua desktop control are distinct qualification modes.

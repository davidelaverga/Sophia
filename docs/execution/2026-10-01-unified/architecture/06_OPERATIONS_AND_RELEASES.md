# Operations, testing and releases

## Source control and current contracts

Use actual AGENTS/CONTRIBUTING rules, exact Node24.21.0/pnpm11.7.0 and frozen dependencies. Preserve runtime artifact identities and gate behavior. Updating a bundle/lock requires the repository's identity-recording process and affected tests; a plan file never changes a running route. Fresh SQL/amendment IDs are allocated from active branches and the actual target ledger, not guessed from an old example.

## Reader-first release

Current API/bridge/Studio readers must understand new records before any writer emits them. Keep old record readability through rollback; do not delete new data to make an older runtime start. Qualify renderer/storage access and credentials separately, with least privilege. No sandbox-disabled fallback or secret-bearing browser proxy.

An operation request binds exact candidate/tree/artifacts, environment, affected contracts/migrations, preconditions, effects, allowance, expiry, verification and recovery. The operator verifies the actual deployed tuple and previous receipts, then executes only approved steps. An owner approval is separate from a coding agent's request. No provider, subscription, schedule, account creation or hosted mutation is authorized by this pack.

## Evidence layers

A labelled UI fixture proves a view. A schema fixture proves structural validation. A pure design model proves only that model. PostgreSQL/RLS tests prove their actual executed database cases. Native/provider tests prove the exact route exercised. A source merge does not prove a hosted release. A completed run does not prove delivered bytes or product acceptance.

Use existing production reports as attributed historical evidence. Do not reset all goals to not_started, and do not mark old reports as rerun. An unavailable required environment is blocked evidence, not a skipped criterion called passed.

## Focused adverse tests

Prioritize uncertain delivery, stale source/CAS, owner mismatch, revoked eligibility, source/credential leakage, delayed cancellation, tool-budget accounting, disconnected observers, private notifications, and simultaneous migration/route changes. Test timers with fake time where possible rather than waiting days or burning a user's quota to manufacture an outage.

The private assistant gate additionally tests that team search, source readers, caches, feed and prompts reveal neither private content nor metadata; immutable shared versions survive private edits appropriately; erasure blocks late retries; and webhook transport uncertainty does not silently incur another provider run.

## Rollback and control

Rollback of a live route first blocks new admission and resolves active effects. A feature flag does not transfer controller ownership or revoke an owner's OS credentials. Keep the old source and exact effective writer settled or isolated before reassignment. Prompt/version rollback applies to new attempts; history remains attributable.

Pause future Bot activation by the available native routine controls and revoke Sophia access as needed. Neither operation proves that already-running cloud computation ended. UI/receipts must preserve that distinction.

## Stop conditions

A session ends with a useful tested slice or a precise blocker and next owner. Do not run endless architecture loops, poll through a model, or weaken acceptance because a problem is inconvenient. The full founder episode remains distinct from smaller release slices. See [working protocol](../operations/WORKING_PROTOCOL.md).

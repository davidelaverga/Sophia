# Product scope and cumulative releases

## Purpose

A small creative team should turn a partly formed idea into useful work, review what was actually produced, and carry decisions and learning into the next attempt. Ordinary conversation remains valid. Not every utterance creates a task, issue, model review, or permanent memory.

Sophia presents one coherent experience across Converse, Explore and Build. It may coordinate multiple execution resources, but the user should not have to operate competing agent managers. Personal space and the team workspace are different audiences; a resource connection never silently joins their context.

## R1 — Create and coordinate together

### R1a: current room plus useful research

Keep main's actual room, Chat/Brief side panel, text-mode behavior, mission ledger, consent and native bridge. Finish the active SMC-M03 work: sourced Markdown/PDF from the selected dsh research route, versioned Knowledge/report readers, usable output/download, and actual authorized voice/text and hosted acceptance. A Markdown success with no PDF is partial for a PDF request. Do not rebuild already-authored registry, byte store, parser or UI under a second feature name.

### R1b: genuine creative work

Deliver intentional Google/OpenAI image generation and comparison, selected bytes retained for edits and handoff, a supported React/TypeScript/Vite prototype, Luis's Preview/Source/Diff editor, a no-secret isolated build/preview and source-preserving handoff to engineers. Selected prior knowledge can enter through explicit import with coverage and current-decision reconciliation. Report, HTML, deck and image-based PPTX output obligations remain; M03 does not close all format work.

### R1c: three engineers and one reviewed application

Davide contributes Codex and Claude Code; Luis contributes Claude Code. Each is separately owner-authorized. Use the Paperclip operational path, real peer dialogue, evidence-based progress review, owner-specific waits and honest capacity observations. Show a meaningful pre-steer risk choice, source-preserving handover when needed, and a real app candidate reviewed in Sophia with both change and preservation constraints checked. Use all three resources when their contributions are useful, not artificial parallelism.

A smaller SCM source-review outcome may ship earlier. It does not silently reduce this full product acceptance. R1 is complete only when the original S1-14 episode and retained format/creative promises are demonstrated or specifically re-scoped by Davide.

## Optional R1 contribution slice: owner-connected personal assistant

The first Bot use is **gather scattered personal knowledge into a private package**, with Sophia ↔ Bot questions, answers, corrections and blockers from the first accepted integration. Review happens in the owner's personal account; a specific shared version then enters the team. The feature can ship beside the team release when its own gates pass. Lack of a personal subscription or inability to connect a Bot must not block ordinary Sophia use.

One template contains the cooperation, knowledge packaging, research/report and review methods. A knowledgeable existing assistant can use the same skill. No catalog of mandatory specialist Bots. Template import does not prove inherited memory, tool availability, security isolation or a completed connection.

## R2 — Precise cooperation and mobile control

Enforce exact source-backed revisions and protected-sibling checks for supported artifacts. Add Storybook/MSW scenarios and Playwright checks, with simulation, replay and actual application evidence kept distinct. Introduce supported in-app native answers, opt-in PWA notifications and mobile controls over the same current action identities. Extend consented discussion-following, selected vision, EN/IT/ES behavior and actual hands-free navigation. Retain selected Notion, Supabase and Vercel workflows without making their connectors a launch prerequisite.

For Bots, qualify one browser/application review and one environment-specific long-running task where the owner's configured environment provides real additional value. Cloud execution continuing after the user disconnects is not itself unique to Bots; Sophia-hosted workers should also do that. Local files and private-network routing still depend on the relevant device being available. Full local GUI control through Cua is a separate optional qualification, not the initial collection requirement.

## R3 — Continuing, adaptive project work

A bounded standing mandate governs multi-week work. Real reset/availability observations can reconsider queued work without expanding permission or spending. Deliver a useful Sophia-native full-stack implementer, an evaluated small execution portfolio and a reviewed procedural-improvement loop with exact versions and rollback. Use the product repeatedly with an external team, including nontechnical contribution, and export source, decisions and remaining work in a portable form.

Cross-owner assistant cooperation is later gated work: dynamic roles, allowed peer edges and direct software delivery, no central model relaying every message. Prefer complementary access/expertise over duplicate generic research. Preserve native engineering and personal assistant resource classes rather than advertising equal controls.

## Not prerequisites or promises

Workspace Agents remain deferred beyond the first release; organizational customer need and verified lifecycle/spend controls must justify reopening. Personal dots, Instinct and Muse are not selected runtimes. The ChatGPT-native/plugin edition is a distinct explored direction, not an implicit dependency here. Jev/Decisions API, Mobbin retrieval and broader computational environments remain optional measured opportunities. No paid fallback, automatic account purchase, general scraping, unlimited autonomy, or inferred private-to-team memory sharing is introduced.

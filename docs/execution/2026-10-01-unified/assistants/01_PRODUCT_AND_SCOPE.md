# Owner-connected project assistants — product and rollout

## Selected direction

Offer one **Sophia Project Assistant** template with task-specific methods. An owner can instead add the same cooperation skill to an existing knowledgeable assistant. Neither creates a new resource entitlement, imports conversation history automatically, or establishes per-Bot isolation.

The first useful episode is scattered-knowledge collection: selected laptop/desktop files, permitted applications and accessible prior research become a readable **personal knowledge package**. The owner inspects and refines the package in personal Sophia, then publishes a specific version through **Share with the team**. A job may be useful without ever being shared.

Sophia and the Bot communicate through tools **and durable two-way messages from the first accepted integration**. Questions, answers, guidance, blockers and useful partial results are part of gathering work, not a later enhancement. Ordinary software carries the messages; no lead model needs to paraphrase every exchange.

## Personal first means the whole workflow

Job title, request, source inventory, messages, attachments, package, embeddings, notifications and intermediate interpretations are private to the authenticated owner. Do not place a private job in a team Paperclip company, project feed, public issue, shared runtime prompt or team search index. An eventual destination project does not change the initial audience.

The import is not automatically a kept personal memory. It is a versioned work product with explicit retention and sharing. Existing note Keep/Let go and Carry/Take back behavior remains distinct. A package is not squeezed into a note-size field or silently converted into a permanent personal identity fact.

## Scope by gate

| Gate | User result | Minimum machinery |
|---|---|---|
| PA-00 | A harmless owner-authorized tool/message round-trip, plus provider limits recorded | Actual OAuth flow and owner mapping; tested template/skill and optional webhook enrollment |
| PA-01 | A personal collection job can ask, answer, be amended, upload a package, and survive observer restart | Owner-private jobs/messages/storage; ingress validation; private UI; no team publication |
| PA-02 | The owner reviews exact content, removes something and shares a chosen version to one team | Immutable share preview, authenticated publication, source/read audience tests and withdrawal |
| PA-03 | An exact web candidate or suitable external workflow is reviewed in the Bot environment | Environment-specific capability proof, bounded task, real evidence and truthful blockers |
| PA-04 | Two separately enrolled owners' assistants exchange useful project questions | Explicit recipient edges, project export grants, peer bounds, no private-memory crossing or native cross-account assumption |

PA-00/01/02 form the optional first assistant release. They do not block the core team release. The full live personal Companion is not required: humans can converse with the Bot through the private job thread. When personal Sophia synthesis is added, its separate runtime and allowance must be qualified.

## Why use this resource

Choose it when the owner's existing knowledge, permitted source access, practiced application workflow, cloud computer, or explicitly contributed allowance adds value. Do not route ordinary public-web research to two external Bots merely to demonstrate parallelism; the native research route can handle that class of task. Server-hosted Sophia workers can also continue after a user disconnects.

Cloud independence is conditional. A cloud browser can work while the laptop is closed; a job that still depends on local commands or desktop-proxied network access must wait when that device is unreachable. Multi-hour reliability is a test requirement, not inferred from the word persistent. [GB-WORK; GB-COMPUTER]

## Onboarding promise

Target **no prompt writing or workflow design required**, not unproven zero-setup provisioning. A native template import, provider login, connector authorization and routine setup may still be necessary. No account signup, purchase, permanent account link or template publication is performed by this pack. Use existing eligible subscribers for the first proof. [GB-TEMPLATE; GB-BILLING]

One assistant is offered by default; research/report/review are methods chosen for the job. Do not require a catalog of specialist Bots. A user can keep their established assistant's context without exporting all of it into Sophia.

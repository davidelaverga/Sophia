## Goal sessions

### PA-04.G1 — Enroll each resource separately

Each actual owner grants selected project work, disclosure, task types and payer policy. Same-account Bots do not double capacity; private collection remains outside team operational records.

**Handback:** exact code/contract/evidence or a specific unmet boundary; report actual versus simulated behavior.

### PA-04.G2 — Bind project assignment and edges

One operational controller creates exact accepted assignments with allowed recipient edges. Bind authenticated owner connection, not a Bot-supplied identity. Deliver only project-published or explicitly exported sources.

**Handback:** exact code/contract/evidence or a specific unmet boundary; report actual versus simulated behavior.

### PA-04.G3 — Run purposeful peer exchange

Two assistants create complementary findings, exchange one useful question/answer, then revise contributions. Transport is deterministic; Sophia does not paraphrase every packet or fabricate independence.

**Handback:** exact code/contract/evidence or a specific unmet boundary; report actual versus simulated behavior.

### PA-04.G4 — Enforce bounded wakes and handback

Coalesce reply wakes, forbid ack loops, detect reciprocal waits and cap chains/exchanges. Retain unknown remote activity; no duplicate retry or reassignment until the selected read-only/effect policy permits it.

**Handback:** exact code/contract/evidence or a specific unmet boundary; report actual versus simulated behavior.

### PA-04.G5 — Integrate and test removal

Sophia aggregates source-linked results into a proposed project decision. Remove a member, race a late reply and reconnect; preserve current privacy/payer boundaries.

**Handback:** exact code/contract/evidence or a specific unmet boundary; report actual versus simulated behavior.

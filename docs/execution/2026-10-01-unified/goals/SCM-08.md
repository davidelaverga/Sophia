## Outcome

Repeated coordination evidence yields one narrow, tested recipe/skill proposal whose exact reviewed bytes can be promoted and rolled back.

## Entry and existing machinery

Useful teamwork is already accepted and comparable episodes exist. This mission is not a launch prerequisite. Do not manufacture “enough evidence” by rerunning paid tasks with no user value.

**Reuse:** Versioned recipe snapshots, source/decision/outcome records, accepted project lessons and real checks. Optional trace systems are diagnostic mirrors, not required truth.

**Required sources:** S03, L01, L03; resolve in [the source register](../sources/REGISTER.md). Read the applicable [architecture](../00_START_HERE.md) and [operations protocol](../operations/WORKING_PROTOCOL.md).

## Goal sessions

### SCM-08-G1 — Evidence slice

**Build:** Select one repeatable coordination defect, matched task/route episodes and measurable outcome. Separate missing capability from a procedural mistake. Record confounders and gaps.

**Handback:** A small justified hypothesis; no personal emotional profile or raw cross-owner transcript.

### SCM-08-G2 — Bounded proposal

**Build:** Propose one allowed recipe/skill change with exact base hashes, scope, expected effect and rollback. A Reflection Coach-like proposer is optional, not presumed implemented upstream.

**Handback:** Proposal changes no identity/voice/safety/consent/personal memory or unrelated global settings.

### SCM-08-G3 — Executed validation

**Build:** Run reproducible regression and held-out cases within a separate approved allowance. Compare accepted outcomes, corrections, cost and latency; hypothetical replay is not execution.

**Handback:** Evidence supports promotion or rejection; no victory claim based only on an LLM’s suggested diff.

### SCM-08-G4 — Human promotion and rollback

**Build:** Apply exact reviewed bytes under compare-and-set, record the new recipe version, use only on new eligible attempts and rehearse rollback.

**Handback:** A stale base refuses; current active attempts remain bound to their earlier identity; rollback restores the selected version.

## Prompt and skill delta

No new perpetual “self-improver”. A bounded reviewer/proposer can read the selected non-private evidence. All changes remain proposals until validated and approved.

A tool’s declaration, backend authorization and effective runtime visibility must agree. Adding a prompt mention is not implementing a capability. New role/configuration changes are hashed/versioned and exercised through the current native registry.

All cases start **not run** in this pack. Add exact candidate, configuration, evidence and result when executed. A synthetic fixture proves only its labeled boundary; it is not a real provider/native/hosted result. Existing tests must remain green on the actual combined candidate.

## Operations handoff

Execute only approved bounded validation/proposal promotion; no automatic production prompt edits or new providers. Retain a tested rollback pointer.

The request must name exact source/artifacts, target, allowed effects, migration hashes/order where applicable, remaining allowance, expiry and recovery. Credentials are secret-store references only. Every effect’s actual result is a receipt, not an optimistic checklist tick.

## No-go / exclusions

No autonomous identity evolution, reward for engagement/positivity, global skill mutation, or claiming anecdotal efficiency as causal proof.

## Stop condition

One narrow proposal is either rejected with evidence or explicitly promoted and rollback-tested. A finding of insufficient evidence is a valid stop, not an invitation to run indefinitely.

Use the [handoff template](../operations/HANDOFF_TEMPLATE.md). Keep pending gates explicit and stop the implementation session at a meaningful boundary; no artificial wait to manufacture long-duration evidence.

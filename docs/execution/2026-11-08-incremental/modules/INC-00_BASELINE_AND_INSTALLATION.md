# INC-00 — Install the incremental programme and assign the first slice

**Owner:** Codex coordinator  
**Implementers:** bounded Claude Code assignments where needed  
**Independent gate:** the combined Codex reviewer/tester  
**Outcome:** current source/authority map, reviewed scope amendment, concrete native and API assignments

## 1. Purpose and boundary

Begin from the running Sophia repository and preserve active work. This is a short implementation-enabling mission, not a new architecture study or a replay of the foundation campaign.

The pack was refreshed against main at 953e5dc3d4c88e491517f3f0d0eaa18216fea98f on 8 November 2026. [The source register](../references/BASELINE_AND_SOURCES.md) records the exact observations and open work. The coordinator must refresh these dynamic identities at kickoff.

The HTML citation/navigation repair and recorded voice-harness issues do not automatically block native connection work. A blocker applies only where the proposed slice crosses the affected boundary.

## 2. Requirements

### INC00-R01 — Recover the actual execution context

Record target repo, branch/worktree, current main, local uncommitted changes, active assignments/PR ownership, runtime unit, environment URLs, and known deployment tuple. Read applicable AGENTS.md, CONTRIBUTING.md, the active execution entry, and the assigned module. An unknown deployment identity remains unknown until observed.

Do not reset, cherry-pick over, or take ownership of unrelated active work. Establish one writable owner per changed file/effect.

### INC00-R02 — Install through the repository's current process

Use a reviewed documentation-only PR for the proposed new execution directory, normally docs/execution/2026-11-08-incremental/. Update the applicable repository-level navigation pointers, such as the repository-specific continuation section of AGENTS.md, docs/README.md where current, and docs/execution/README.md, using the existing installation process. Do not edit the previous pack's internal 00_START_HERE.md or other frozen files. Preserve historical packs as history.

Assign currently available contract-amendment and migration identifiers; this pack does not reserve an identifier in the repository merely by naming it. Do not edit frozen prior specifications to make the new scope look historically present.

Record this pack's latest combined reviewer/tester roster and significant-UI gate. The launch prompt is not a replacement AGENTS.md.

### INC00-R03 — Map existing seams before adding records

Produce a small mapping from each new logical concept to the current implementation or a named addition:

- Owner resource, entitlement identity, contribution grant, capability profile.
- Frozen execution binding, allowance commitment, current-authority check.
- Native runner enrollment, command journal, session correlation, control settlement.
- Input/routing record, exact source manifest, typed effect, receipt projection.
- Coding mission/project manager, role assignments, Paperclip continuation ownership.
- Design hold and exact candidate approval.
- Source review, automatic review coverage, deployment and app-verification evidence.

Map contracts, generated OpenAPI/types, domain/persistence, API routes, worker dispatch, execution-host boundary, and existing Studio components together. Do not prescribe a parallel table where a current record can safely carry the extension.

### INC00-R04 — Resolve the first executable connection choice

The first qualification uses one selected owner and one native provider on an owner-controlled environment. Prefer an existing environment already capable of official native sign-in. Choose the concrete owner/host based on availability; the pack does not invent a reachable device.

Record exact installed native tool, adapter candidate/version, repository/worktree permission, account provenance plan, command-ID persistence location, and intended network path to Sophia. Qualify T3 behind the single runner port first. If a critical mapping fails, identify the exact failed operation and select the smallest alternative behind the same contract.

Do not install a broad desktop platform, new hosted multi-tenant product, or second scheduler to answer a narrow connection question.

### INC00-R05 — Prepare real owner and payer actions

Use the existing account/service configuration to identify a bounded API payer and initial test allowances. Only a real owner can finish their own provider sign-in or enlarge a resource contribution.

Prepare the exact connection/grant form, operations covered, maximum allowed use, and expiration before asking for a missing owner action. Never request a password or consumer session token in a coding thread.

An initial local/API grant need not be team-wide. Cross-member API use is a later required INC-01 case, with a concrete contribution preview.

### INC00-R06 — Freeze meaningful first tasks

Select a small read-only repository analysis for native qualification and one low-risk repository implementation task with an observable app result for INC-02.

Record purpose, allowed files, forbidden effects, base/source version, success observation, review, deployment target, and allowed test scope. Choose a task whose implementation and live result can be verified; a no-op edit or generated report alone cannot establish the complete repository delivery path.

### INC00-R07 — Establish the design lane

The designer reads current production design rules and records existing tokens, primitives, layout, key accessibility behavior, and relevant product decisions in the existing documentation or PRODUCT.md/DESIGN.md.

Select the pinned Impeccable distribution/source and reviewed installation mechanism. Inspect skills and hooks; preserve permission boundaries. Setup and documentation alone do not require a new significant-UI approval. The first material changed candidate does.

### INC00-R08 — Publish assignments and evidence ownership

Use [the work assignment template](../templates/WORK_ASSIGNMENT.md). Assign independent contract, native-adapter, API/resource, and design tasks only where the scopes do not overlap.

The Codex coordinator explicitly gives the independent Codex thread the review/test role, the relevant spec, current diff, and evidence requirements. Do not copy the author verdict as the review conclusion.

### INC00-R09 — Bound unresolved questions

Record uncertainty as a named qualification or owner action with a next step. Do not block the whole programme on unknown provider telemetry, a dormant paid grant, or an unrelated historical acceptance failure.

Changes to product scope, significant design, financial authority, or provider route eligibility need their actual decision owner. Routine code organization and feasible implementation details belong to the assigned agents.

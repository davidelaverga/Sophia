# A client reads what a newer API adds without failing

> 2026-10-15 · Codex P1 on #336: a Studio still open from before a deploy refuses a property it doesn't know, so its
> brief would fail to read; #334's chat names put the room's snapshot in the same place. Luis: «Sí, haz que el Studio
> tolere campos desconocidos».

## What was measured

- The validators a client reads the API with (`@sophia/contracts/validate`, generated by
  `scripts/generate-validators.ts`) refuse any property their schema doesn't list. 352 schemas say
  `additionalProperties: false`.
- So any additive amendment (A01–A18 added properties to responses 40-odd times) breaks every client still running the
  previous build until it reloads: the Studio, and the media bridge.
- The API validates requests with its own Ajv (Fastify). Responses go through Fastify's serializer, which drops a
  property the response schema doesn't list. Neither depends on these validators.

## What changes

- **The readers drop what they don't know** (`removeAdditional: true`). Where a schema says
  `additionalProperties: false`, a property it doesn't list is removed, at any depth. The value reads as the shape the
  reader was built for: nothing unknown is kept, shown or sent back.
- **What breaks the known shape is still refused:** a missing field, a wrong type, an unknown enum value, a bad format.
- **A guard in the generator:** dropping inside `anyOf` is safe only while at most one branch is an object. Ajv drops
  while trying a branch, even one that then fails, so a second object branch could lose its fields. The generator now
  fails if a reader's schemas hold such a union. Today none of the 87 schemas the 45 readers reach does.
- `getMission?names=1` (#336) stays: it keeps the brief's shape for any reader built before this.

## Checks

- `validate.test.ts`:
  - a snapshot with a new top-level field and a new field on a message reads as the known shape;
  - a receipt with an extra field reads equal to the receipt;
  - a frame with an extra field is the advance it was;
  - a wrong type or a missing field beside an extra one is still refused.
- `pnpm check`: the generated validators, the whole unit suite and the browser suites in CI.

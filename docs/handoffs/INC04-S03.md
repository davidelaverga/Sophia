## 3. Design, bound to C01–C08

**Records (NEW 0107; all RLS enabled, no policy, no application grant)**

- **`sophia.capacity_observations`: the sealed parent.** It is bound to one closed, versioned scope (`scope_version = 1`, `route_kind = 'api'`). Every scope column is NOT NULL, so its uniqueness is real and never weakened by NULLs:
  - the owner, the canonical accounting root `account_id` and the provider;
  - the exact payment path the evidence was taken through: `connection_id` and its `credential_revision`;
  - `route_id`, `model`, `effort` and `operation`.

  The recorder derives owner, account, provider, route, model and effort from the connection's own rows, never from labels. The named credential revision must be the connection's current one. A model selector on a window must equal the parent's model.

  Provenance columns:
  - `source_kind = 'operator_recorded'` only (custody);
  - `verification` ∈ {operator_verified_call, operator_verified_console}, the 0104 vocabulary;
  - `evidence_ref` (custody outside the database), `source_channel`;
  - `window_set_ref` plus `window_set_version`: the authoritative applicable-window set;
  - optional `source_sequence` (an authoritative order).

  Coverage and window columns:
  - `coverage` ∈ {complete, partial, unavailable}. A none-applicable claim is refused: no qualified mechanism exists;
  - `required_window_refs`, non-null and non-empty only when coverage is complete;
  - `reflection` ∈ {unknown, none, some, all}, a separate C04 fact that is never consumed;
  - `observed_at`, `fresh_until`, `recorded_at` (the database clock);
  - `window_count`, the canonical `payload_sha256` and `observation_key`.
- **`sophia.capacity_observation_windows`: the children.** Each has:
  - `window_ref`, an optional `window_epoch`;
  - `scope` ∈ {account, model, spend, concurrency};
  - `model_selector`, required exactly for a model window and equal to the parent's model;
  - `unit`: provider-native text, never converted;
  - `value`: nullable, **never projected or used**;
  - `verdict` ∈ {admits, exhausted, unknown}: the source's own statement, never derived from a value;
  - `applicability` ∈ {known, partial, unknown};
  - `reset_at`.
- **`sophia.capacity_observation_revocations`.** Insert-only revocation: one per reading, with a reason. Validity and revocation are judged at the caller's instant.

**Sealing and replay (C03)**

- `sophia.record_capacity_observation(jsonb)` and `sophia.revoke_capacity_observation(uuid,text)` are migration-owner only: EXECUTE is revoked from PUBLIC and granted to no role, following the `qualify_api_account` precedent.
- The recorder validates closed keys and shapes, then inserts the parent and every child in its one call.
- A window can be inserted only while the recorder holds the transaction-local sealing setting for that parent, and the setting is cleared before the call returns.
- A deferred constraint trigger refuses a commit whose child count differs from `window_count`, so there are no half observations.
- UPDATE, DELETE and TRUNCATE are refused on all three tables.
- Same key and same canonical payload returns the original sealed reading, including under a concurrent race: `INSERT … ON CONFLICT DO NOTHING`, then compare the hash. The same key with a changed payload is a 23505 conflict.

**Record-time refusals (22023)**

- `observed_at` in the future;
- `fresh_until <= observed_at`;
- **`fresh_until` later than any window's `reset_at`**. This is the epoch fence: a reading never outlives its window's reset;
- duplicate refs, or more than 20 windows;
- complete coverage that does not equal exactly the window refs, has a window that is not `applicability = known`, or has an empty set;
- a model window without its selector;
- unknown keys.

**Read: `sophia.selection_capacity_observation_at(grant, connection, account, p_now)`**

STABLE, granted to no role, and called only from the definer snapshot.

- **Visible readings.** A reading is visible only if its exact scope matches the candidate's current connection, current credential revision, route, model, effort and operation, AND `observed_at <= p_now` AND `recorded_at <= p_now`. One fixed instant; no backfill time travel.
- **No reading.** NULL, which is the exact baseline.
- **More than one stream.** A stream is (channel, window set, version). Multiple streams give `conflict`; windows from distinct readings are never merged.
- **Choosing within a stream.** The latest `observed_at` wins, then the higher `source_sequence`. Equal times without distinct authoritative sequences give `conflict` unless the payloads are identical. A late-arriving older reading never wins.
- **Revoked.** If the chosen reading is revoked at `p_now`, the result is `revoked`.
- **Otherwise** it returns `recorded`, with: id, times, `fresh` (`fresh_until > p_now`), coverage, required refs and the windows. Windows carry no value, evidence, channel, reflection or limitation text.

**C04 (two independent gates)**

- Observations never write, release or reclassify ledgers, reservations, claims or uncertain holds. 0107 has no trigger or function touching them.
- There is no arithmetic between an observation and the Sophia ledger, and no second wallet. Reflection is recorded and never used.
- This is **not** full R07 reconciliation.

A value a4e8 accepted (numerically equal to the current revision 1, canonicalized from the bigint column as 1) is therefore refused with 22023, both as a new reading and as a replay. I introduced this text cast in the R1 review update, when I switched the canonical revision to the request's own value. This is not a rounding claim. The reviewer's witness was static; the raw-JSONB tests below establish the actual result.

**Repair (credentialRevision only):** a helper, `capacity_observation_revision(jsonb)`.

- It requires a JSON number.
- It checks the number is integral and within 1 to 2^63-1 **as numeric, before any conversion**, so nothing ever rounds into a revision.
- It returns the bigint.

It is used in all three places:

1. the canonical form, so the request's own value stays in the payload and `1`, `1.0`, `1.00` and `1e0` all hash as `1`, exactly as a4e8 did;
2. the new-reading guard, which still requires the value to equal the connection's current revision;
3. the historical lookup, by that exact revision. A non-integral or out-of-range value finds nothing, so it falls through to current admission, which refuses it.

A changed integral revision never reuses another revision's receipt. There is no change to `accountQualificationRevision` or `sourceSequence` parsing, and no generic numeric policy. Everything else from R1 is unchanged: the lookup-first replay, caller-supplied hashing, 23505 conflicts, the new-key guards, the seal, privacy, no replay writes, and the read with its current-bound partition and C05.

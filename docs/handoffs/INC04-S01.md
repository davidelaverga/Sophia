## Outcome

`@sophia/domain` now has `evaluateSelection`, a pure, deterministic, advisory function that, given one trusted snapshot of a new-work request and its candidate resources, returns either a proposed candidate with ranked alternatives or a specific waiting, denied, blocked, refused or invalid result, with closed reason codes for every candidate. `projectSelection` is the only serializable view of a decision, filtered for one viewer.

What it does not do: it reads nothing, admits, reserves, dispatches, rebinds, resumes or calls nothing, has no runtime caller, no persistence, schema, migration, contract, route, flag or UI, and changes no existing behaviour. Nothing in its input authenticates anything: a future trusted server caller must derive every fact and existing admission must recheck all of them before any effect. It is one source component, not a live S01 service, not INC04 and not activation.

No acceptance case has evidence from this work. All eighteen AC-04 cases remain open, as do every native, owner, deployed-authorization and application gate.

## The contract implemented

The R2 proposal with all seven corrigenda of the independent review and root choices C01 to C07:

- **Order.** Structural validation (`invalid_input`), then active work (`refused_active_work`), then request-wide holds (`blocked`: goal hold, stop or completion, mission Stop, source withdrawal, design hold, authority, an operation-level refusal, unproven independence, an unsettled prior attempt, each including unknown), then per-candidate filters, then the winning policy scope, then ranking.
- **Completeness (C01).** Limiting windows and protected-reserve dimensions are proved by a witness independent of the lists checked: a covered witness must name a non-empty required set and every member must be present and fresh; `none_applicable` must be explicit; partial, unknown or empty coverage fails closed. Reserve protection applies to every consuming role. A conservative no-reading policy replaces readings, never reserve protection.
- **Proofs (C02).** Conservative capacity policies, route overrides, cross-payer authorizations and project allowances are resolved propositions, checked for proposition, issuer, authorizer, exact owner/project/account-group/payer/route/family/operation scope, role, status and validity at `evaluatedAt` (a standing policy may have no expiry). Unknown, stale, revoked or mismatched proofs fail closed.
- **Authority (C03).** Cross-member use is derived from the owner and actor refs; contradicting facts are a `fact_conflict`. A required contribution grant that is null is `grant_missing`; the grant must cover the actual owner, project, role, operation and strict settings, with expiry judged at `evaluatedAt`. 0094's refusal codes pass through verbatim.
- **Modes (C04).** Pin selects only its target or waits/denies. Prefer with an absent target waits; a prohibited target denies; an unavailable target falls back within its payer, or to a payer named by a current cross-payer authorization, which never competes with an eligible target. An empty pool waits with `no_candidates`.
- **Settings (C05).** One effective strict setting (a manual request, else a winning Pin's; a conflict between them is invalid). Prefer and default seeds are soft, proposed only when declared and granted for the candidate's own provider instance. Provider-native values are never equated across instances; accepted and observed settings are always `unknown`. Keyed facts (options, models, share grants) canonicalize identical duplicates and fail closed on typed conflicts (`true` is not `'true'`).
- **Projection (C06).** One whitelist for rows, proposal, alternatives, settings and fallback. A viewer the caller has not permitted to see the request gets one uniform restricted shape. Otherwise the resource owner sees its codes; a shared viewer sees only a coarse limitation and the fields shared with them; anything else is omitted, a hidden proposal is `withheld`, and no counts are given. The internal decision's throwing `toJSON` is an accidental-serialization guard only.
- **Determinism (C07).** The same canonical input gives the same data decision, including under any permutation of candidates, sets and keyed facts. Timestamps are strict RFC 3339 normalized to UTC microseconds. Errors and reported codes are sorted before bounded reporting, which never changes a status or a selection. The correlation tuple names declared input revisions and the normalized instant; it is not a proof of equal facts, an equal decision or a permission, and nothing is hashed.
- **Bounds.** Structural only, from existing conventions: 200 candidates (A51 page), 50 refs per set (0094), 20 per declared list, 10 options per model and 20 values per option (0096), 40 reported errors or codes (0038), 200-character refs and values. No quota, reserve, funding or provider number is introduced.

## Decisions and changes

Two choices go slightly beyond the R2 text, both conservative: a cross-payer authorization enters a Prefer pool only while the preferred target cannot serve, and a Prefer `fallback` record is emitted whenever another candidate than the target is proposed. Error paths name a candidate by its ref, never its position, so a reordered invalid input reports the same errors. No new authorization, wider scope, dependency or identifier was needed.

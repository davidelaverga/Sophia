## Decisions and changes

**`db/migrations/0114_capacity_exposure_custody.sql`** (new; 0114 allocated; 0113 not needed or touched).

*Custody.* Append-only records, migration owner only:
- scopes (the 0107 exact scope and its qualification ids and revisions);
- windows (R2 `window.register.v1`);
- issuers (R2);
- bindings of one 0107 reading window to one registered window and kind;
- binding revocations;
- dimension mappings;
- attributions (R2);
- effect finality (R2; every distinct payload of a subject, folded by the accepted `foldFinality`).

*Codec and validation.* R2's typed TLV codec, byte for byte. The SQL test reproduces the frozen identities of the window,
key, issuer, attribution and finality fixtures. Validation runs in R2's order: keys, then grammar with a real calendar,
then cross-field rules, then append-time semantics.

*Receipts.* An exact replay returns its receipt (judged before any current check). A different payload under a recorded
key is one sticky conflict, whose retry returns the same receipt. Nothing is ever updated.

*Seal and privileges.* Each write happens only inside its own append's seal. Update, delete and truncate are refused. RLS
is on, with no policy, and no application grant on any table or function.

*The read.* `selection_capacity_exposure_at` (STABLE) gathers the facts of the current reading:
- its bound windows and their partitions;
- every model reservation whose 0109 identity names the scope's account, in **any project**, capped at 200;
- truth classes, counts, conflict, overflow and history (conflict, ordinal 16);
- finality appends, attributions and mappings.

It never reads money state, `ended_at` or cost.

*The candidate.* `selection_api_candidate` is 0107's body byte for byte. It adds an `exposure` key **only** when the read
transaction set `sophia.capacity_exposure` to `w1`.

**Persistence** (`selection-snapshot.ts`, `capacity-exposure-custody.ts`, `index.ts`):
- `readSelectionSnapshot(…, { exposure })` sets that switch only when asked. Asked, every API candidate must carry the
  key, else the snapshot is unavailable; not asked, nothing changes.
- Typed append wrappers map the database's fixed refusal codes to `CapacityCustodyRefused`.

**Domain** (`index.ts`). Exports the accepted pure module as the namespace `capacityExposure`, because its `Window`,
`Unit` and other names collide with the kernel's. The module, its tests and its fixtures are byte-identical.

**API** (`selection-exposure.ts`, `selection-snapshot.ts`, `routes/selection-preview.ts`, `app.ts`).

*The adapter's count rules.*
- **Counts** are `so_far` lower bounds through an applicable mapping. `unknown` and `no_separate_reported_class` are
  absent. Two mapped sources must agree.
- **Unresolved effects.** These carry no count and no finality, and make the set incomplete:
  - a conflicted mapping;
  - a conflicted, overflowing or full truth row or history;
  - a conflicted finality fold;
  - a reported count above a final total.
- **The bound** is null; δ is 0.

*The outcome per window.*
- Proven over, or exactly zero headroom, is **exhausted**.
- Only a complete, unconflicted result whose effective floor is above zero is **unchanged**.
- Everything else is **unproven**. Exhausted outranks unproven, which outranks unchanged.

*The kernel input.* Unproven is 0107's own `basis: none` shape. Exhausted marks 0107's witness window as `exhausted`; with
no witness, nothing is made up.

*Wiring.* The route guard and `/ready` require 0114's two markers only with the switch on. `server.ts` does not set it.
The 0105, 0109 and 0110 core checks are unchanged.

**CLI** `scripts/record-capacity-exposure.ts`. Operator transport for the eight appends, for disposable databases only.
It prints receipts, never payload values.

**Not touched:**
- the pure module, its tests and its fixtures;
- contracts, OpenAPI, GEN and SDK; the lock and toolchain; the runtime identity;
- `server.ts`; the UI;
- `DESTINATION_MAP` and the Source Map. Their rows are in the external handback for Routing's ownership; there is no
  commit, so the same-commit map obligation is deferred to integration.

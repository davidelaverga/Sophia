## INC01-30813-EXPIRY-F01 (P1, inherited; ACKed and closed here in 0096)

**Cause.** 0092 judged connection and qualification expiry at transaction start. A prepare-send that waited on the
project lock past the expiry still marked the possible send, and the dispatcher sent it.

**Repair, in 0096 only (0092 frozen):**
- every expiry uses `clock_timestamp()`;
- prepare-send runs the whole recheck again after the account reservation's lock, immediately before the possible send;
- admission rechecks expiry after its last lock wait, before any write;
- GO already rechecks immediately before its grant.

**Regressions.** Real PostgreSQL, through the dispatcher, gateway, fsynced journal and FakeT3, each with an unexpired
control:
- prepare-send waiting on the project, for a qualification and for a connection;
- an input waiting on the account reservation;
- an admission waiting on the goal.

**Mutations X01–X03.** These restore each gap; the results are in the export.

### CC005-E7-F01 (P1): private diagnostics

**Fix.** No text a native runner or transport returns reaches an answer, the journal, an operation reason, an exchange,
an event or a view. That covers failure messages, unlisted codes, deliveries and statuses, transport and thrown-error
text, and read failures. The mapping names only the pin codes it lists, and everything else is a fixed diagnostic. The
dispatcher's thrown-port reason and the proxy's unreachable reasons are fixed too, and the dispatcher no longer logs a
thrown error's text. Identities, outcomes and commitments are unchanged.

**Tests:**

- the PG dispatcher, after erasure, through the operation reason, events, view and journal;
- a throwing port;
- the host exchange answer and operation reason.

### CC005-E7-F02 (P1): cumulative binding context

**Fix.**
- `owner_runner_lineage_ineligible` rechecks the context of every operation that may already be on the native thread:
  the create and every earlier `possible_send`, `unknown`, `received` or `settled` input. That covers the instruction,
  the manifest, each selected source as frozen (hash and revision, with its closure), and the withdrawal mark. It also
  refuses a project audience that moved since the create.
- It runs at input admission, under the project lock and before any write, and in `owner_runner_source_ineligible`, so
  prepare-send, 0093 delivery and GO all apply it.
- An input's selected source must equal its create's frozen `(id, sha256, eligibility_revision)`.
- The erase hook denies admitted, unclaimed inputs of an affected session at once, without marking their own content.

**Unchanged.** The create's manifest is never rewritten. No native purge is claimed. No binding, account, refund or
resend is touched. The Stop stays source-exempt, and read and reconcile are as before.

**Tests:** the create's selected source, its instruction, an earlier input's instruction, and a source revision, each
both before admission and with the input admitted before prepare. Also the audience, the unchanged control with Stop
after erasure, and GO between delivery and GO through the configured proxy, channel and agent.

### CC005-E7-F03 (P2): one character semantics

**Fix.** A character is a code point everywhere: the A50 and A47 schemas, SQL `length()`, and the gateway's
`checkEnvelope` and `checkPayload` (`isChars`). SQL's `owner_runner_blank` is exactly the set of characters JavaScript's
`trim()` removes, refused at admission before any write or allowance use.

**Tests:**
- admitted and sent through the dispatcher: 4001 and 8000 supplementary characters, a 120-character title, mixed text,
  and an input of 8000;
- refused before allowance: 8001 characters, a 121-character title, and non-ASCII and line-break blanks;
- the API schema agrees at 8000 and refuses 8001 and 121.

## Outcome

A project writer's message can be recorded as an `automatic_v1` input through two new database writers and typed
persistence callers, with no effect. No user-visible behaviour changes: no route, contract amendment (A49), generated
type, persistence index export, worker, UI or composer uses them, and no existing file or function changed.

- **Contract.** Explicit, required, exactly `automatic_v1`, checked in TypeScript before the query and again in SQL
  (`NULL` or anything else: 22023). No boolean, no default; the legacy writers never create an input.
- **Authority.** The verified actor; the project row locked first (send: project, then conversation, the legacy
  order); the caller must be an admin or editor now, before any earlier request is read. Audience (project members,
  settings revision) and context references (message seq, conversation and erasure revisions after the append, the
  writer's role) are resolved by the database; nothing of that is accepted from the caller.
- **Idempotency.** The legacy `conversation_requests` table and `start`/`send` operations, with a distinct semantic
  (contract, version, digests). Same key and semantic: the original receipt, after later messages and after
  read-only. Changed words, legacy↔automatic, start↔send: 23505. Withdrawn or erased: 40001.
- **Record.** `sophia.saved_conversation_inputs`: ids, contract, origin `text`, audience, context references,
  explicitly absent addressing (no mentions, no reply target, basis `none`), state `recorded`. No text, title, digest,
  summary or history. Readable by current members while the conversation is open (RLS); no write grant to any login.
- **Receipt.** `{conversationId, messageId, inputId, interactionContract, contractVersion, input:'recorded',
  effect:'none'}`.
- **No effects.** No reply, attempt, binding, command, outbox, runtime command or reservation, proven on a project
  where legacy `askSophia:true` admits a pending reply with all of those.

Not proven or not present: HTTP compatibility — no API file is added, and omitted, `null` or non-boolean `askSophia`
at HTTP stays **untested here** (the code refuses them with 422, but no existing test pins those cases; only extra
fields are pinned) — routing, mentions, attention, assessment, funded Answer/Explore/Build, personal/private or voice
inputs, app acceptance.

# Extension register — not first-release prerequisites

These entries preserve useful future directions without putting them into the first product's dependency graph. Each names a concrete insertion point and the benefit to measure. They do not claim newly audited compatibility or implemented capability.

## E01 — Gemini Live Extended Thinking

Add `gemini-3.8-live-extended-thinking` as an explicitly selected voice profile for difficult live reasoning. It is a separate model from the chosen normal Live route [G-01]. Keep the same media/tool/context contracts. Measure response latency, task quality, interruption recovery and total usage on comparable real conversations. Do not silently add reasoning delay to the default voice experience.

## E02 — Google per-participant transcription and interpretation

For S2 discussion-following, select Google's `gemini-3.5-transcribe-live` route as the first transcript adapter to detail; the model catalog establishes the ID, not its full streaming protocol. Preserve authenticated track identity and original utterances. A separate interpretation mode can translate a participant without replacing source meaning or automatically sharing private speech. Complete its exact streaming/retention audit before implementation. [G-01]

## E03 — Recorded-video review

Add a Google multimodal review job over an explicitly uploaded recording, with source timestamps, captured frame ranges and associated console/test logs. Keep “observed”, “inferred” and “verified by executable check” separate. This enriches feedback on the application's actual behavior; it is not a substitute for the browser tests.

## E04 — Broader image recipes

Keep the two principal image adapters and explicit Pro/Flare candidates. Add Google image Lite for rapid inexpensive variations after comparing its actual usefulness, not just nominal price. Add masks, asset-region edits and cross-provider reference conversion as separate capability declarations. Preserve selected source assets and licences; failed re-generation does not overwrite them. [G-01, G-07, OA-01, OA-02]

## E05 — Project handoff tools and eligible enterprise sync

Extend selective imports with an explicit Send-to-Sophia MCP tool in supported ChatGPT/Claude clients. Build the reverse bridge only for an actual documented entitlement/API. Enterprise compliance access is a distinct administrative product, not a benefit of an ordinary personal subscription. Keep source coverage/omissions visible and never label a shared chat link as the whole project. [P-02]

## E06 — API-backed managed execution

Add an owner-authorized API execution route to the existing ResourceBinding contract for work that must continue when personal hosts are unavailable. It is not an automatic spending fallback or a new account-sharing path. Record exact provider session, budget and retention behavior; preserve accepted source and goals across handoff. This direction remains useful even when native subscriptions are the preferred initial economics.

## E07 — Fast structured judgment, including Jev

Introduce a `judge(evidence, questions)` capability for bounded classification only after obtaining task-labelled evidence. Candidate jobs are attention triage, contradictory-claim flagging and whether a progress report is supported by supplied observations. Counts and elapsed time stay in code. A classifier does not set the team's belief, authorize an effect or provide adversarial-content security. The prior Jev research remains an extension lead; its current endpoint and model terms were not re-audited for this pack.

## E08 — Persistent research workspaces and kernel-style context handling

A Prime-inspired persistent programmatic workspace may help research where data objects and repeated analysis dominate. Add it beneath a native specialist's workspace contract, not as another project-manager root. Compare against dsh's existing PTC plus durable files before adding a persistent kernel, its process recovery, data egress and deletion responsibilities. No claim that ordinary PTC is already persistent. [DSH-18]

## E09 — Executor-side efficiency from Pi/SoL-Pi

Observation packing, action fusion, reduced outputs and online context compaction remain valuable executor research. Apply a measured mechanism inside the chosen native execution profile rather than importing a second full executor merely because of a benchmark. Compare completed outcome, human repair, latency and cumulative spending on the same tasks. The earlier course is background; no new Pi/SoL-Pi code adoption is made here.

## E10 — Additional browser and design-source tools

PinchTab can become an optional private browser-inspection adapter; native-desktop control can become a separately scoped future capability. Neither is public tenant infrastructure or a reason to automate ordinary deploy dashboards. Mobbin retrieval remains a small authorized reference experiment, not a bulk scraped corpus. Keep browser inspection, human screen observation and execution authority separate. [P-02]

## E11 — Richer knowledge and procedural learning

Add stronger repo-claim freshness, embedding or multimodal retrieval and external memory providers behind the current eligibility contract. A new index does not own accepted decisions. Procedure improvement can propose changes to skills, context recipes and routing with a competent comparison and rollback. Private memories, identity and permissions are not automatic optimization targets.

## E12 — General team platform and market expansion

Additional channels, richer membership/decision charters, mobile native shells, templates for courses/campaigns/community projects and hosted execution can widen adoption. Preserve one cooperative guide and an artifact-centered experience. Test whether the additions reduce reconstruction and enable meaningful contribution; do not recreate an enterprise PM dashboard by accumulation.

## Promotion rule

A concrete user need and a bounded implementation proposal admit an extension experiment. Success requires a better useful outcome or substantially simpler operation against a competent current route, without violating source, authority or privacy boundaries. Inconclusive, rejected and no-change are legitimate outcomes. No calendar deadline or cost estimate is asserted here without task sizing and actual usage.

## Native-editable PowerPoint export

The first deck path retains editable HTML and exports one full-slide image per PPTX slide. Add a separate semantic slide representation and native text/shape/chart exporter when that becomes a real user need; do not call the existing raster compiler natively editable. Reuse the same asset/source/version/publication contracts. Compare visual fidelity, notes, fonts, accessibility, client editability and export/reimport behavior on actual decks. This extension does not replace S1's working export or S2's source-preserving HTML edits. [OLD-03, OLD-07]

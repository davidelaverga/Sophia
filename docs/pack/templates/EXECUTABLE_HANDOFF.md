# Executable project handoff

## Outcome and boundaries

Goal/revision, user benefit, acceptance checks, non-goals, explicit change and preservation requirements, reserved decisions.

## Exact starting material

Repository/base commit or source-bundle identity; frontend components; dependency lock; approved image assets; design tokens; behavior/scenario definitions; build/run instructions. A screenshot accompanies the source—it does not replace it.

## Integration map

For each mocked behavior: what is simulated, the intended real interface, existing repository fit, the allowed change surface and the evidence required. Record mismatches rather than guessing.

## Context and authority

Accepted decisions and eligible source IDs; omitted optional material and reasons; excluded private context. Resource owner, selected worker/coordinator arrangement, existing operation grants and cumulative allowance. Never include credentials.

## Return

Candidate source/commit, preview/environment, changed and preserved areas, actual checks/failures, unresolved gaps and amendment coverage. Provider completion, human acceptance and deployment remain separate facts.

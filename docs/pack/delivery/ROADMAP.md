# Three cumulative product releases

## Release 1 — Create, coordinate and steer together

The complete product is a shared voice-first Studio for Davide and Luis. It imports selected prior project context, researches, generates visual assets through Google/OpenAI, creates source-backed reports/decks and runnable UI prototypes, lets Luis edit source, and coordinates all three owner-operated engineering resources. It presents actual progress and permission needs, reviews on a five-minute project heartbeat or manual request, and turns application co-review into a change/preserve brief for the worker team.

The application preview is real and source-linked. Existing engineer database/deploy integrations are used. Sophia's own Supabase persistence is built, but first-party Notion/Supabase/Vercel management connectors are not prerequisites. Exact mechanically bounded artifact edits are Release 2.

**Milestones:** M1.1 real voice-to-work; M1.2 prototype/context/three-resource coordination; M1.3 application review/formats/integrated founder use. See the [goal index](GOAL_INDEX.md).

**Release episode:** import selected prior context; correct current decisions; discuss by voice; generate directions; build and edit a runnable prototype; approve a roadmap; assign useful work to the actual three resources; answer a native owner permission; inspect a technical-lead decision; steer the returned application; reconnect; use an accepted lesson in the next brief. A screenshot-only substitute does not satisfy the episode.

## Release 2 — Precise cooperation and remote control

The product adds meaningful milestone capture, optional cooperation opportunities, exact supported artifact revisions, interactive scenarios, executable browser review, supported native permission responses inside Sophia and mobile access. Required owner actions remain separate from optional invitations and routine progress.

The room gains consented discussion-following, attributed transcription and a single presence policy. Normal conversation, original attributed meaning and output language remain separate. Selected Notion/Supabase/Vercel management workflows and external notifications extend the same project, not a second history.

**Release episode:** the team explores an alternate behavior, revises a precise component, observes peer dialogue and a real review milestone, answers a supported request on mobile, tests the integrated flow and returns to the same current decision/source after leaving. Unsupported OS/native login still has an honest owner handoff.

## Release 3 — Adaptive continuity and native application execution

The product maintains authorized progress across multiple goals and longer absences. It can assign a native dsh implementer to a real full-stack feature, select an economical/strong execution arrangement and retain useful learned procedures under explicit evaluation and rollback.

The release includes repeated external-team use, a useful nontechnical contributor workflow, resource visibility and a deliberate migration of supported old routes. It does not promise unrestricted autonomy or equal competence across arbitrary repositories.

**Release episode:** a team returns after time away, understands actual progress and pending choices, starts the next useful goal, sees a previous lesson affect the work, receives a native feature candidate and independently evaluates it. A proposed procedure improvement is promoted or rejected from actual evidence; either outcome is legitimate.

## Calendar and progress

These are release sprints, not three assumed two-week boxes. The goal graph fixes outcomes and dependencies; dates attach after the first integrated implementation slices reveal the team's velocity. No separate Sprint 0 is required. A weekly demo shows the currently functioning product and its known gaps, not only isolated infrastructure or a mock walkthrough.

A sprint closes on its complete episode plus the affected recovery/ownership checks. It does not wait for universal proof of every future capability, and it does not silently remove a failed criterion. The original v0.2 priorities remain intact. [P-01]

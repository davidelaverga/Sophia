## Work sequence

1. Implement the first schema slice: project/member, command, event and job/outbox records. Write explicit migrations and access tests before wiring clients.
2. Implement authentication, server-derived actor identity, expected-revision admission and transactional outbox.
3. Implement a current snapshot plus sequence-based SSE replay; render the admitted work in a minimal real Studio view.
4. Use the contract examples as fixtures, not native evidence. Extend typed schemas into generated clients as the implementation lands.

## Acceptance evidence

- Both real member sessions can access the shared project; a different account cannot.
- Same request/payload returns the same command; different payload under the same key conflicts.
- A disconnect between commit and acknowledgement recovers the existing result.

## Adverse checks

- A stale expected revision cannot overwrite a newer accepted change.
- A UI render or notification click cannot manufacture work completion.

## Session and handback

Create the actual attempt binding at execution: goal ID, native session, owner, worktree/base commit, writable scope, runtime unit, existing authority and cumulative allowance. The brief is not a permission grant. Keep source and assignment identity in every handback. Use [SESSION_HANDOFF](../../templates/SESSION_HANDOFF.md); return commands actually run, exact result versions and limitations. A failed attempt remains part of this goal rather than disappearing when a new coding chat starts.

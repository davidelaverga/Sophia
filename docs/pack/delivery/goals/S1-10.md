## Product result

A worker asks its coordinator a useful question during execution, gets an answer and continues without a human copying prompts or a lead model relaying each message.

## Work sequence

1. Implement the durable cross-runtime envelope and recipient assignment checks; native dsh peers use their existing team machinery.
2. Deliver through the actual native adapter boundary; wake an idle recipient through a supported command, not a perpetual model polling loop.
3. Track persisted, delivered, incorporated and acted-on states separately. Coalesce routine receipts and suppress acknowledgement-only exchanges.
4. Separate per-worker source areas and the shared deployment/database operation owner.

## Acceptance evidence

- A real Codex/Claude peer question and answer changes or confirms the ongoing approach before final completion.
- A second Claude resource performs independent useful work or review under the same goal arrangement.
- The technical lead sees relevant outcomes without paraphrasing each peer packet.

## Adverse checks

- Redelivered mail is deduplicated.
- A stale assignment/epoch cannot receive new instructions.
- Messages cannot expand permissions or race the designated shared-effect owner.

## Session and handback

Create the actual attempt binding at execution: goal ID, native session, owner, worktree/base commit, writable scope, runtime unit, existing authority and cumulative allowance. The brief is not a permission grant. Keep source and assignment identity in every handback. Use [SESSION_HANDOFF](../../templates/SESSION_HANDOFF.md); return commands actually run, exact result versions and limitations. A failed attempt remains part of this goal rather than disappearing when a new coding chat starts.

## Work sequence

1. Bind the preview to source revision, environment and declared real/mocked services.
2. Implement separate Interact and Select-for-discussion modes with frame/target capture and exact source context.
3. Admit a clear authorized review intent; let the lead reconcile it with the current work and brief revision.
4. Show returned candidate, changed/preserved areas, tests and remaining uncertainty; retain the stable preview.

## Acceptance evidence

- A complete working application preview is usable inside the supported preview boundary.
- An ambiguous target is clarified; an unambiguous authorized edit does not require redundant ceremony.
- The team sees the actual worker amendment and checks its resulting candidate.

## Adverse checks

- A stale comment stays on the old preview unless deliberately retargeted.
- An unembeddable external site gets an explicit supported review route rather than bypassed headers.
- S1 does not label instruction-based preservation as guaranteed surgical editing.

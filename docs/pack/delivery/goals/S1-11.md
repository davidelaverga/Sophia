## Work sequence

1. Implement brief/roadmap/goal proposals and explicit acceptance with definitions of done.
2. Implement one coalesced active-project heartbeat plus event/manual triggers and a review lease.
3. Give the lead fresh bounded evidence, prior interventions and outstanding decisions; exclude known waits from automatic stagnation claims.
4. Implement continue, inspect, steer, fresh alignment, independent review, hold/replan and ask-human outcomes within the current mandate.

## Acceptance evidence

- Review work progress wakes the lead immediately and returns an evidence-linked decision.
- One periodic review examines the project’s three resources without triple context duplication.
- A meaningful change/preservation instruction reaches the proper goal coordinator/worker and is visible to the team.

## Adverse checks

- Two coincident triggers do not create duplicate lead turns.
- A single ordinary test failure does not force a mission pivot.
- A no-change review updates status without an unnecessary spoken interruption.

## Session and handback

Create the actual attempt binding at execution: goal ID, native session, owner, worktree/base commit, writable scope, runtime unit, existing authority and cumulative allowance. The brief is not a permission grant. Keep source and assignment identity in every handback. Use [SESSION_HANDOFF](../../templates/SESSION_HANDOFF.md); return commands actually run, exact result versions and limitations. A failed attempt remains part of this goal rather than disappearing when a new coding chat starts.

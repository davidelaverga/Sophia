The team generates actual image alternatives through both chosen vendors, selects an asset and reuses the same bytes in later source work.

## Work sequence

1. Implement the durable image-job lifecycle and private asset storage with source/consent provenance.
2. Implement Google Interactions generation/edit using response_format and model_output image parsing; store:false is explicit.
3. Implement OpenAI direct Images generation and multipart edit using the dated Sunburst snapshot. Make Google Pro and Flare selectable comparators.
4. Expose an intentional comparison and selection flow. Record actual request configuration, outcome, usage and human feedback without declaring a global winner.

## Acceptance evidence

- At least one real Google and one real OpenAI generation are stored and viewable.
- An image edit uses the selected source image and produces a new candidate.
- Selecting an image does not discard alternatives or trigger more paid generations.

## Adverse checks

- Refusal, no image output or timeout produces a truthful failed/uncertain result.
- A retry after ambiguous acceptance is not blindly charged as another identical job.
- Unrelated source edits preserve the selected asset reference.

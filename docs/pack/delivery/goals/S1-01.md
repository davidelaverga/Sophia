**Human owner:** Davide  
**Design state:** `design_ready`  
**Implementation:** `not_started`  
**Dependencies:** none

## Product result

A new repository has a repeatable toolchain and an identifiable dsh artifact; a developer can start the first product slice without guessing versions.

## Read before coding

Read the root AGENTS contract, then [02_DSH_BOOTSTRAP](../../architecture/02_DSH_BOOTSTRAP.md), [10_OPERATIONS_AND_TESTS](../../architecture/10_OPERATIONS_AND_TESTS.md). Resolve these source IDs in [the register](../../sources/source-register.json): DSH-01, DSH-02, DSH-03, DSH-19, DSH-20. Read the relevant pinned upstream implementation before changing that interface. These sources establish mechanisms; the proposed destination files are new Sophia code.

## Source destinations

- `package.json`
- `pnpm-workspace.yaml`

- `docs/`

## Work sequence

1. Create sophia-next as a separate repository; preserve the existing app and outstanding obligations.
2. Check out the exact dsh pin outside the product tree. Record Node 24 exact version and pnpm 11.7.0; resolve and commit ordinary application dependencies.
3. Create the workspace packages and bundle exports. Produce a pinned runtime artifact and bundle archive; record their digests.
4. Install the named profile manifest from the verified declaration types. Run the trusted configuration dump and retain startup diagnostics.

## Acceptance evidence

- A clean second checkout resolves the same lock and artifact identities.
- The profile includes dsh-base and the Sophia bundle, not another root loop.
- The document source map and code destination map are committed, with unbuilt paths still labelled.

## Adverse checks

- A missing/incompatible Sophia bundle does not become a healthy runtime.
- A comments-only or wrong-row patch is diagnosed rather than silently accepted as the intended configuration.

## Session and handback

Create the actual attempt binding at execution: goal ID, native session, owner, worktree/base commit, writable scope, runtime unit, existing authority and cumulative allowance. The brief is not a permission grant. Keep source and assignment identity in every handback. Use [SESSION_HANDOFF](../../templates/SESSION_HANDOFF.md); return commands actually run, exact result versions and limitations. A failed attempt remains part of this goal rather than disappearing when a new coding chat starts.
